## Objective

Finish the Site side of the Core/App extraction: keep only deployment-owned implementation/current continuity, remove copied/transient nonsemantic debris, correct stale branch/publish guidance, and qualify an observable historical `.topics` Reduction before any semantic artifact deletion.

## Done Criteria

- Site contains no byte-identical App/Core documentation or developer helper copies that have an established owner elsewhere.
- Transient local validation outputs and the pre-extraction Tooling source snapshot are absent from current deployment source.
- Site first-contact text and Pages workflow describe the current thin `master` deployment and its actual scripts instead of the historical `refactor` monolith.
- Historical Tooling/Viewer artifacts are represented by a qualified `tiinex.reduction.v1` boundary before deletion.
- Destructive reduction receives an exact immutable Git source identity, exact candidate/preimage set, currentness basis and a qualifying reduction-preflight receipt; unresolved preflight forbids deletion.
- The surviving Site semantic frontier is the deployment Workspace/current deployment task plus the qualified Reduction/current follow-up material needed to explain the boundary.

## Scope

Do not copy historical implementation into Core/App, rewrite old artifacts, infer completion from file age, or delete semantic artifacts merely because Git would retain them.
