# Viewer Navigation Parity Recovery — Active Major

## Objective

Activate the next Foundation major by recovering recognizable PoC navigation behavior across Feed, Tree, artifact opening, Lineage, search/filtering, selection, and return context on `refactor`, using current qualified shared read-model/runtime semantics and keeping Tree path truth distinct from declared semantic Lineage truth.

## Done Criteria

- Feed, Tree, and Lineage are implemented as distinct Viewer projections that answer distinct human questions without inventing semantic authority.
- Tree remains derived from material/logical path truth; Lineage remains derived from declared semantic relations and qualified resolution state.
- Feed and Tree open the same stable artifact identity, and artifact → Lineage → return preserves the relevant discovery/navigation context.
- Search, filtering, and display state do not mutate semantic relation truth or manufacture missing-parent/ancestry claims.
- Feed ordering remains deterministic and presentation-only.
- Focused deterministic tests cover identity consistency, Tree/Lineage separation, filtering invariants, return context, and cached-versus-uncached semantic equivalence where optimization is used.
- Useful Viewer/projection optimization work from `playthings` may be selectively ported only with evidence of semantic equivalence; the branch is not merged wholesale and is not semantic authority.
- Missing shared Tooling/runtime semantics are surfaced as explicit prerequisites instead of being reimplemented privately in Viewer.
- Kodax returns technical Evidence plus a self-contained Handoff/carrier stating what changed, how it was validated, known risks, and the exact next action.
- Sigma receives a normal browser path only after machine qualification and judges first-use comprehension, Feed/Tree/Lineage recognizability, navigation fit, and return-context behavior.
- Anchor reconciles Kodax technical evidence and Sigma human evidence and decides progression; Kodax does not self-accept product parity.

## Scope

Implementation target is `refactor`. PoC interaction evidence comes from `master` and `poc-monolith`; `playthings` is optimization/reference evidence only. This major covers navigation/read interaction only. It excludes Create/Continue/Reference/Use-as authoring UI, Workspace/source takeover, Time Portal, export/Handoff manufacture, Extension/Host Bridge, Playthings world/placement experiments, broad visual redesign, public release/deployment, and unauthorized remote mutation.
