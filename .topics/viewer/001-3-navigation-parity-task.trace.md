# Viewer Navigation Parity

## Objective

Recover or explicitly disposition the PoC navigation value across Feed, Tree, Lineage, filtering/search, selection, and return context using shared qualified artifact/path/lineage read models.

## Done Criteria

- Feed, Tree, and Lineage remain distinct projections answering distinct human questions.
- Tree is driven by material/path truth; Lineage is driven by declared semantic edges and does not infer ancestry from path proximity.
- Opening selected Lineage from Feed or Tree preserves a truthful return context.
- Search/filter/display options do not mutate semantic truth and expose qualified schema identities distinctly from supporting material kinds.
- Missing, mismatch, ambiguous, historical, and current states remain distinguishable.
- Equivalent loaded artifact/path/lineage facts are inspectable through Tooling before browser parity is claimed.
- Focused machine checks pass before Sigma reviews comprehension and navigation fit.

## Scope

- Planned implementation; hold until the relevant `005` Tooling read/navigation primitives are qualified and cheap enough for routine iteration.
