# Make Playthings occupy the browser viewport and turn resolver-supported cross-repository gates into continuous geographical passages between repository realms.

## Objective

Respond to Tiinusen's fourth manual observation that the world language is beginning to make sense but remains too small and visually disconnected. Preserve read-only Tiinex semantics while making Playthings feel like entering one multiverse rather than viewing several repository boards.

## Done Criteria

- Playthings uses the available browser viewport instead of remaining constrained to the ordinary Tiinex shell width or leaving a large unused lower surface.
- Normal Tiinex Feed/Tree configuration remains unchanged before entry and after Return to Tiinex; fullscreen behavior is experiment-local only.
- Repository realms stay bounded and visually distinct, but their layout uses the available wide viewport to make realm populations and landmarks materially larger and easier to read.
- For up to three visible realms, layout order is topology-aware: the realm with the strongest resolver-supported cross-repository Parent connectivity is placed centrally when three realms are present; layout remains presentation only.
- Every rendered cross-Verse gate is still backed only by resolved Parent crossings already present in the Playthings model.
- A rendered gate reads continuously as settlement road → realm boundary portal → shared void causeway → destination boundary portal → destination settlement road.
- The causeway and realm approach roads are static at Now and add no ambient movement. Newly observed gates continue to use the existing bounded delta animation only.
- No road, topology placement, causeway shape, visual proximity, or centrality becomes relation, priority, truth, or repository authority.
- Existing semantic morphology, quiet realms, uncertainty preservation, ZIP/local realm affinity, gate aggregation, reduced-motion support, and delta playback remain intact.
- Business and Docs repositories remain unchanged context; GitHub source adapter repair and Viewer persistence remain excluded.
