# Playthings dedicated Anchor: generative world and asset integration

## Objective

Continue Playthings as its own focused experiment line: preserve the current one-earth, lineage-driven, presentation-only semantics while replacing placeholder graphics with a scalable Edwardian fantasy/true-steampunk visual system; make every movement, construction, scene transition, road, schema storage journey, and resting migration have an observable lineage/material reason; make Places navigable generative scenes rather than static prefurnished pictures; and keep the entire world performant, deterministic, inspectable, and artifact-backed.

## Done Criteria

- The recipient Anchor performs local discovery before implementation and treats the carried Site source as authoritative code truth for this package.
- The recipient preserves the Playthings semantic boundary: presentation may reconstruct movement/place/roads but never invent Parent, Relation, transition authority, timestamps, qualifications, repository realms, or semantic geography.
- One shared earth remains the default across loaded workspaces/origins; cross-origin lineage must not be split into arbitrary repository islands.
- A living Plaything continues to represent a current living lineage leaf, with history driving movement and Live becoming still when no new observed event is active.
- Normal artifact-derived visuals are Born from nothingness and normally Expire to nothingness; expired artifacts do not remain as decayed clutter unless a later grounded presentation rule explicitly requires a residue.
- Workspace/Place artifacts are built, not spawned completed: a causally eligible Plaything travels to a legitimate destination, performs Work/Construction, and the place grows from observed state.
- Plaything locomotion and verbs use a reusable fixed animation grammar rather than one bespoke animation count per schema; schema/type resolves presentation verbs while artifact objects provide nouns/targets.
- Plaything interactions include a real door-open/enter/exit animation so actors do not walk through walls when entering Places.
- The visual direction is fantasy-first with Edwardian true steampunk infrastructure: steam, pistons, belts, gears, flywheels, pipes, gauges, relays, incandescent lighting, telegraph-era instruments, and direct-current electricity; no transistor-era electronics and no magic technology/glowing-crystal power system as the default explanation.
- Root fallback is presented as an ancient natural Root Tree with a door, not a portal machine. It remains presentation-only and cannot become semantic Place/Parent/Relation authority.
- Root Tree traffic uses entrance/clearing sockets so repeated journeys can form shared trunks and junctions rather than every road beginning at one exact pixel.
- Roads remain reconstructed presentation only, mature deterministically through 1-10 wear levels, cost less than grass when established, respect Place/actor footprints, and render below Place cores rather than across trees/buildings.
- Z-order is explicit: terrain/background -> roads/paths -> Place shell/floor -> furniture/props -> Playthings/actors -> foreground architecture -> effects/VFX -> UI/overlays.
- Places use modular building/interior assets rather than pre-furnished static rooms. Capacity derives from current world state: e.g. 30 sleeping Playthings require 30 sleeping positions, while zero sleepers do not justify decorative beds.
- Parent/child Place lineages may be projected as nested navigable scenes (building -> floor -> floor -> department/room) when the lineage genuinely qualifies those artifacts as Places; the projection must not fabricate semantic hierarchy beyond resolved lineage.
- Entering a Place may fade and swap the active Playthings scene like a loading zone. Stairs/doors/child Places may swap to another scene; only the active scene needs full rendering.
- If Follow is enabled, following persists across door/stair/loading-zone transitions so the same Plaything remains the camera subject inside buildings and across floors.
- A Journey Reason Resolver chooses Place travel only from grounded candidates in observed material/lineage. A Plaything must not visit a place merely because it looks visually convenient.
- Schema documents remain blueprints, never living Playthings and never castles/workshops because of the schema they describe.
- A discovered schema may be presented as studied/carried/stored in an already legitimate Library/Archive Place, with Look Inside exposing stored schemas, but this storage journey remains presentation-only unless Tiinex independently resolves a real relation.
- Quick Place inspection may use a dialog with its own Playthings canvas; full Enter uses the scene stack. Both reuse the same generative world grammar.
- Sleeping/resting Place interiors scale from actual occupancy and remain inspectable; the prior idle thresholds remain <4 days normal, 4-7 long idle, >7 resting, evaluated against historical playhead time during playback and real time at Live.
- Fork/sibling presentation preserves the three-way choreography frontier: at the branch point the returning actor, continuation actor, and new sibling may depart concurrently, with the sleep-return actor not increasing historical resting counts merely because it is a presentation clone.
- Playthings returns to a true fullscreen world with Viewer controls/HUD floating over the world rather than consuming a large inline header/layout band.
- DALL-E/image generation is used as a source artist, not trusted as a machine-readable atlas generator. Chosen sources are normalized by code/tooling into exact frame grids, transparent PNGs, pivots, footprints, animation timing, and manifests before runtime use.
- Artwork sources, asset contracts, meaningful implementation receipts, and subsequent decisions are preserved as Tiinex Evidence so the Playthings experiment remains recoverable without chat archaeology.
- Viewer performance and the worker-backed/non-blocking Playthings-entry direction are preserved; expensive world preparation must not return to first-render UI blocking.
