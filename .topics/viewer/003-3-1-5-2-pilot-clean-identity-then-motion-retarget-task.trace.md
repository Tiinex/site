# Pilot-Mediated Clean Identity Then Motion Retarget

## Objective

Execute one bounded two-phase human-mediated visual-production session. Phase 1 creates a new static Plaything identity master with no animation semantics. Phase 2 uses the exact Phase-1 identity result as identity authority together with a separately carried UAL walk authority to generate one eight-frame walk source. Pilot guides both human turns, preserves exact observable inputs/results, then returns one lineage-correct Evidence + Handoff package to Anchor.

## Done Criteria

- Pilot grounds from the generic Business Pilot Role and the declared human-mediated external-execution process.
- Phase 1 uses only the carried neutral 1x4 layout reference plus the exact carried character-identity text; no motion authority or prior animated Plaything reference is introduced.
- Phase 1 returns exactly one clean static turnaround identity master with four neutral full-body views and no animation/action progression.
- Pilot preserves the exact Phase-1 generated identity bytes when exposed by the host.
- Phase 2 uses the carried walk motion authority first and the exact Phase-1 identity master second. The Phase-1 identity is not replaced by a prior animated identity sheet.
- Phase 2 returns exactly one 2x4 eight-frame walk source for that new character.
- Pilot records actual human-visible inputs, actual attachment identities, host/provider anomalies, and byte/pixel-fidelity facts when observable.
- Pilot does not visually accept, reject, postprocess, normalize, redesign, or promote either output.
- After Phase 2 succeeds or becomes blocked, Pilot authors one execution Evidence and one Pilot-to-Anchor return Handoff, manufactures the return package, and stops immediately.

## Scope

Two external generation turns in one bounded Pilot session: one identity-master turn, then one motion-retarget turn. No retries unless separately authorized; no whole 8x8 master; no product acceptance; no prompt redesign after execution begins.

## Expected Evidence Lineage

The execution Evidence should preserve the exact generated identity master and exact generated motion source as same-stem native files where practical, for example `003-3-1-5-2-2-generated-identity-01.png` and `003-3-1-5-2-2-generated-motion-01.png`, followed by a Pilot-to-Anchor return Handoff. Stable promotion remains Anchor's responsibility after review.

## Retained Review Boundary

Anchor retains identity-quality review, motion review, alpha/layout checks, deterministic postprocess, retry disposition, process update, and stable promotion outside `.topics`.
