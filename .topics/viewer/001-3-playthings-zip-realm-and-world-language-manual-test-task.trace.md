## Objective

## Done Criteria

- Local/ZIP records may project through one configured workspace repository only when the workspace-to-repository affinity is unambiguous from already configured repository sources; the binding remains projection-only and is counted explicitly.
- A workspace whose repository affinity is ambiguous remains unbound rather than being guessed.
- Docs, Business, and Site may therefore materialize as separate repository Verses from local ZIP-loaded records without repairing or depending on GitHub transport.
- Cross-repository Parent targets may resolve across those projection-bound records and become explicit world gates; no non-Parent relation is silently invented.
- Living sprites represent current lineage heads. Historical non-head artifacts become world-history/memory marks, while semantically useful structural artifacts may project as landmarks.
- Each repository Verse has an original realm treatment and terrain language; Tiinex/docs, Tiinex/business, and Tiinex/site receive distinct presentation archetypes without changing underlying artifact identity or semantics.
- No idle world animation is introduced. Movement remains evidence of newly observed delta only; settled Now remains still and reduced-motion is respected.
- The visual language remains original and must not reproduce Black Mirror, Thronglets, Tuckersoft, Nintendo, or other third-party character/art/UI assets.
- Business and Docs repositories remain unchanged context; GitHub source-adapter repair remains explicitly outside this Task.
