# Playthings synchronized forks, location inventory, and living roads

## Objective

Refine the shared-earth Playthings experiment toward a fantasy MMO-RPG interaction language without changing Tiinex semantics: when a sibling/fork occurs, move the existing living representation back to the actual branch point and fan three presentation actors out simultaneously; let places expose their currently resting Playthings through an inspectable location/inventory dialog; and make history-caused traffic easier to become navigationally useful while requiring connected corridor evidence before something is visually called a path or road.

## Done Criteria

- A split event resolves the actual historical branch point and approaches it before fan-out.
- At the fork beat exactly three presentation actors overlap at the same branch point: sleep-return, continuation-return, and new-sibling.
- All three fork actors begin their outgoing motion at the same event time; their paths may have different lengths and settle independently while the timeline advances only after the fork presentation completes.
- The sleep-return actor is presentation choreography only and cannot create another living lineage or increment settlement occupancy.
- The continuation actor returns toward the location/state occupied by the previously living leaf while the new sibling travels toward its new generated scene.
- If the source leaf already had a resting habitat, the sleep-return choreography returns to that same habitat; otherwise it uses the nearest already-built legitimate habitat when available and may fall back to the prior leaf location without inventing a building.
- The existing source actor remains suppressed only while fork choreography owns its visible pixels and returns to the normal living/resting projection after the event.
- Persistent Organization/Workspace places expose Look Inside from their Playthings selection menu.
- Look Inside opens an in-world location dialog with RPG/inventory-like resident slots for currently resting Playthings.
- Location resident count is derived from current living-leaf resting assignment; the dialog does not create semantic membership, residence, occupancy artifacts, or new Tiinex truth.
- Each sleeping resident can be selected, opened in the in-world Lineage Verse, or inspected in Artifact Detail.
- Route traffic begins wearing ground after two completed traversals, may become path after four, and road after eight, all presentation-only and prefix-stable.
- A* travel cost can prefer these increasingly worn routes when the reduced cost beats another route.
- Isolated high-wear segments are displayed as worn ground/entrance apron rather than being visually promoted to a road; path/road visual language requires a connected corridor.
- Related continuing scenes receive a small deterministic soft attraction toward already-used traffic corridors in addition to legitimate lineage-place attraction; unrelated roots remain unaffected by road attraction.
- Castle/workspace footprints remain physical routing/placement obstacles substantially larger than a Plaything.
- Existing schema blueprint boundaries, stable actor identities, resting lifecycle, Find/LOCAL attribution, in-world Lineage Verse, Tech Tree, package reconciliation, Viewer performance safeguards, and canonical Create/transition authority remain intact.
- The implementation stays decomposed: placement scoring is separated from world history generation rather than pushing playthings.world.js beyond the static source-size discipline.
- Playthings cases, TypeScript, architecture, browser imports, UI shape, smoke, integration, and static regression validation pass with zero introduced static debt.

## Scope

- Tiinex/site Playthings presentation, navigation, fork choreography, sleeping-location interaction, road wear, placement scoring, CSS, and focused regression coverage.
- Site-only Handoff package for human testing.
