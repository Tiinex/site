# Human-First Common CLI — Transport And Cold-Sufficiency Closure

## Objective

Resolve the bounded human-first acceptance hold reported by Sigma after the technically clean fresh acceptance: further simplify the ordinary shared CLI/return interaction where needed, restore one-carrier operator transport clarity, and independently prove that cold recovery does not depend on a pre-populated Workspace or useful ambient cache/state.

## Required Investigation

Use explicit RCA discipline before source mutation:

`Sigma observation → exact fresh reproduction → owning layer → root cause → minimum correction → regression/isolated proof → return candidate`

Distinguish host presentation behavior from portable Tooling behavior. If the extra loose markdown outputs or quote-style routing block are caused by ambiguous Tooling projection/guidance, correct that owning projection. If they are purely host rendering choices, make the Tiinex return contract explicit enough that an ordinary fresh consumer can unambiguously present the established transport surface without bespoke instructions.

## Scope

- Shared portable Site Tooling and its public human/LLM common path only.
- Ordinary `ground`, `ground --continue`, `author`, and `handoff` interaction/projection where needed to reduce remaining decision-path cost.
- Return-transport projection/guidance after a successful public `handoff`.
- Fresh isolated cold-start proof with empty target Workspace and no useful pre-existing Tiinex continuation/cache/runtime state.
- Small permanent regressions only for true invariants established by the correction.

## Acceptance Invariants

- One public CLI surface remains shared by humans and LLMs; no Sigma-, Transport Operator-, or LLM-only façade.
- Ordinary happy-path output is decision-first and materially bounded. Full qualified receipts remain deliberately available on the same surface.
- Successful return transport has one canonical operator payload: the manufactured Handoff package. Canonical Evidence/Handoff markdown remains carried Workspace content and is not projected as additional required loose transport files by default.
- The return result exposes one short canonical routing snippet suitable for direct copying. In markdown-capable host guidance, the established snippet must be represented as a fenced code block rather than quote/prose boilerplate.
- The transport projection must remain truthful: package identity, readiness/verification, and exact Start/Continue-from routing cannot be hidden merely for brevity.
- A genuinely fresh receiver with an empty output Workspace and without useful prior continuation/cache state can bootstrap from the exact Start contract, transfer to portable Tiinex, ground, materialize, act on the bounded Task, and manufacture a qualified return carrier.
- Cache/runtime reuse may improve performance but cannot be required for correctness. If Tooling uses cache, the run must expose enough identity/state evidence to distinguish an optimization from hidden authority.
- Preserve all carrier-major `006` fail-closed grounding/recovery invariants and the technically accepted no-post-takeover-glue path.

## Required Cold Proof

Construct an isolated acceptance fixture/run that begins with:

- the exact Handoff package,
- the declared Start trace/bootstrap payload,
- a new empty receiver Workspace/output directory,
- no `.tiinex/continuation.json` inherited from another run,
- no useful pre-existing materialized Workspace,
- no correctness-bearing cache assumption.

Then exercise the ordinary public path. If a cache is naturally created during the run, distinguish newly-created runtime optimization from pre-existing state and verify that deleting/omitting it before the run does not change correctness.

Do not require the model to hand-parse ZIPs, JSON receipts, or internal state after Tooling takeover.

## Transport Projection Check

Reproduce the fresh-host result that surfaced a carrier plus two loose markdown documents. Determine whether the portable `handoff` projection or its next-action text encouraged that presentation.

The target ordinary operator handoff is conceptually:

- one canonical Handoff package to move,
- one short copyable routing block,
- no extra operator decision about auxiliary markdown files.

Do not remove canonical Evidence/Handoff artifacts from the Workspace/package; correct only the transport-facing projection/guidance unless evidence proves a deeper issue.

## Interaction-Cost Check

Measure the whole ordinary fresh common path, not only three individual command outputs. Record command count and raw output volume for the normal decision path, and identify any remaining repeated receipt/detail that does not change the next action.

No exact byte/token threshold is pre-authorized. The criterion is materially simpler, recognizable ordinary use without loss of decision-critical state or fail-visible recovery.

## Retained Side-Track Requirement

Preserve Sigma's carrier rule as a separate retained requirement:

- serial depth is the default,
- explicit side-track may select any ancestor and allocate the next free sibling among that parent's children,
- descendant suffixes are truncated in the new path,
- sibling branching must not become an automatic response to long paths,
- Anchor may normalize collisions at ingress.

Do not broaden this tranche into a large carrier-topology redesign. If a small isolated Tooling correction is clearly required to prevent current ambiguity, return RCA and recommendation separately rather than delaying the primary acceptance closure.
