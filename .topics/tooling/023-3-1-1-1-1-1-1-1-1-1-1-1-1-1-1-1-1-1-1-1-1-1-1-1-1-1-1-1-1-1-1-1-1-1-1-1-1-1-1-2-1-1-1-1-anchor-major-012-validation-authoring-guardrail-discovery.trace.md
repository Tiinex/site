# Major 012 Validation And Authoring Guardrail — Anchor Discovery

## Discovery Intent

- Intent: determine why Tiinex VS Code 0.1.4 can present a clean artifact after a narrow Quick Fix while missing schema-permalink, Parent-coherence, Parent-target integrity and Workspace-identity defects, and identify the smallest current shared-core repair rather than making Sigma manually debug each case.
- Starting Question: which guardrails already exist in current Site/Docs authority or historical `ai-provenance`, which are absent from the active editor-assistance composition, and where should Loom repair them without moving semantic truth into the VS Code adapter?

## Discovery Field

- Field: Sigma fifth-dogfood video and observed generated Handoff/Package Builder behavior; current Site shared `editor.assistance`, artifact validation, integrity validation, lineage integrity projection/apply, Handoff workspace package-source projection; current Docs Root publication/reference authority; historical `Tiinex/ai-provenance` VS Code continuity validator as implementation evidence.
- In Scope: ordinary trace schema-reference fidelity, Parent artifact/schema coherence, targeted Parent/self integrity, deterministic repair planning, diagnostic line anchoring, Role/Party endpoint candidate projection, and Workspace artifact identity in package selection.
- Out Of Scope: new schema families, rewriting current Root semantics, broad `ai-provenance` migration, Viewer parity, Playthings branch sync, deployment/release, or destructive Reduction work.

## Discovery Method

- Method: inspect the current shared-core call chain used by VS Code editor assistance; compare it with the already-present Site lineage integrity planner; inspect current Root publication rules; then inspect historical `ai-provenance` continuity-validation mechanics for proven guardrails that are absent from the current composition.
- Current Adapter Finding: the VS Code diagnostics adapter already uses native `DiagnosticCollection`/Code Actions and delegates to shared core. The remaining correctness defects therefore belong primarily below the host adapter.
- Current Core Finding: editor assistance currently audits one record with exact-schema authority and offers a narrow c14n-v2 self-integrity hygiene repair. It does not currently compose full Parent-target continuity or schema-permalink fidelity before returning clean/repairable state.
- Existing Shared Capability Finding: current Site already has lineage-integrity projection/apply mechanics capable of resolving Parent context, planning Parent/origin repairs, and detecting integrity cascade effects. The preferred fix is composition/reuse of these mechanics, not a second validator inside `Tiinex/vscode`.

## Discovery Boundaries

- Semantic Authority Boundary: Docs remains canonical. Historical `ai-provenance` checks are evidence of useful mechanics only; current shared core must implement only rules supported by qualified current Docs authority.
- Publication Boundary: Root distinguishes local/unpublished truthful-relative recovery from published schema references, which use immutable canonical locators when available. A global "all links must be permalinks" rule would be overreach.
- Integrity Boundary: self integrity and targeted Parent integrity are different claims. Resealing self proves only the current artifact bytes; it must not imply that a declared Parent-target checksum or Parent recovery path is valid.
- Workspace Identity Boundary: a Workspace artifact is not equivalent to repository basename. Package-local selection must preserve distinct qualified Workspace identities even when their physical source snapshots can share one repository.
- Endpoint Boundary: Handoff `Kind` remains exactly `role | party | unknown`. Qualified role/party choices may improve authoring and automatically supply references, but UI convenience must not infer holder identity, acceptance, or authority.

## Discovery Outcome

- Outcome: no new semantic schema turn is required before the next Loom repair. Current Docs authority plus current Site lineage mechanics are sufficient to strengthen shared editor-assistance and package-source projections. The missing work is principally composition, exactness, diagnostics mapping, and regression coverage.

### Historical ai-provenance harvest basis

- The historical continuity validator parses Envelope/Current/Parent schema references, Parent Trace/Origin and footer entries as one continuity surface.
- It recognizes commit-pinned GitHub/raw schema permalinks and can verify the referenced commit/path against a matching local Git checkout using revision/path checks and exact `git show` bytes.
- It flags ordinary trace `Envelope Schema`, `Current Schema`, and `Parent Schema` references when commit-pinned schema permalinks are required or unreadable, while treating schema-note/local cases separately.
- It compares declared Parent Schema with the resolved Parent artifact's Current Schema and preserves missing/unreadable/cyclic Parent states rather than guessing.
- It can compute targeted continuity checksums for `self` or a referenced Parent/target through relative or commit-pinned recovery and reports checksum mismatches explicitly.
- These mechanisms should be translated into current shared Tooling only where current canonical contracts still authorize them; they must not be copied wholesale with stale provenance-specific semantics.

### Required shared-core correction

- Compose artifact audit with continuity/reference/integrity qualification so a single editor-assistance result cannot claim clean when a qualified guardrail fails.
- Preserve exact authority state: unavailable immutable material or unresolved Parent/repository mapping produces visible unresolved/blocked state, not a fabricated repair.
- Add deterministic repair planning for canonical schema-reference hygiene and Parent-target/self integrity only when all needed source bytes and identities are qualified.
- After any repair, re-run the same complete guardrail set before returning clean.
- Give each finding a stable field/footer location projection suitable for native VS Code diagnostics/Quick Fix.

### Required authoring/package correction

- Project qualified Role/Party endpoint candidates from current Workspace material and let the VS Code authoring surface select them; automatically emit exact reference when selected. `unknown` remains free-text.
- Replace repository-basename `workspaceId` as semantic Workspace selection identity with a stable identity derived from the qualified Workspace artifact. Keep repository snapshot deduplication separate.

## Interpretation Limits

- Limits: this Discovery does not assert that sandboxed consumers can fetch arbitrary remote material. Local Git history, carried snapshots, and already-qualified source providers may satisfy immutable resolution; otherwise the result remains unresolved.
- Limits: it does not authorize network writes, auto-repair of ambiguous lineage, automatic publication, or schema semantics invented from historical `ai-provenance` code.
- Limits: human dogfood remains required after Loom qualification; technical PASS alone does not close Major 012.
