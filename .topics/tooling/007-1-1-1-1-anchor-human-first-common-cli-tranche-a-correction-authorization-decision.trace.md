# Human-First Common CLI Tranche A — Correction Authorization

## Decision

Anchor accepts Loom's reproduced progressive-disclosure defect and authorizes the minimum local shared Site Tooling correction needed to complete the existing Tranche A Task.

The controlling Task already authorizes a minimal shared Tooling change when a defect is reproduced and root-caused. The `ground` receipt field currently projected as `authority.mutationBoundary.sourceMutation: false` must not be interpreted as overriding that Task/Handoff work authority: inspection shows it is a static Tooling operation-safety boundary emitted by cold-consumer grounding. Because the fresh Loom return used that projection as a reason to withhold an otherwise Task-authorized local source correction, this ambiguity is itself a reproduced common-path authority/ergonomics defect.

Loom is therefore authorized to:

- implement the minimum progressive-disclosure correction in the shared public CLI help surface and its existing focused regression spine;
- reproduce and minimally correct the grounding projection ambiguity so operation mutation behavior is clearly distinguished from semantic work/delegation authority;
- mutate only the local carried Site Tooling source required by those bounded corrections and tests;
- keep `remoteWrite` false and perform no commit, push, release, deployment, Viewer, Extension, package-topology, or schema-semantic redesign work.

If correcting the projection requires changing canonical Task/Handoff/schema meaning rather than clarifying Tooling composition/output, Loom must stop and return that contradiction for Axiom review.

## Basis

- Loom reproduced default/global help exposing the full advanced/internal catalog despite presenting `operations` as deliberate advanced discovery, and localized the defect to `cli.help.js` plus help dispatch in `cli.run.js`.
- The existing Tranche A Task explicitly says to apply the smallest shared Tooling correction justified by reproduced evidence and includes shared portable Tooling implementation in scope.
- The fresh Loom return explicitly withheld that correction because `ground` reported `sourceMutation: false` under `authority.mutationBoundary`.
- Current Tooling source shows cold-consumer grounding hard-codes that mutation boundary as an operation-safety property and `projectAuthority()` exposes it under the authority projection. This placement is sufficient to reproduce a false authorization inference in a zero-precontext consumer.
- Sigma's controlling human ergonomics requirement remains one public human/LLM path without bespoke protocol interpretation.
