# Foundation Human-First CLI And Carrier UX

## Decision

- State: accepted
- Subject: post-cold-start-decomposition acceptance and the next bounded human-first Tooling progression
- Decision: Loom's cold-start qualification decomposition return is accepted as progression. Anchor independently reproduced permanent acceptance at 54/54, focused/tooling at 4/4, and regression-aware static at two inherited unresolved / eleven resolved inherited / zero introduced.
- Carrier Authority Read: no new semantic clarification is required for carrier lineage. Current Tooling already declares carrier lineage as a human progress/retention projection only and explicitly states that it never replaces artifact Parent/Trace/Origin, Handoff authority, or source truth. Carrier major/dimension therefore remains convenience continuity and must not force or synchronize artifact lineage advancement.
- Human CLI Finding: the ordinary human command surface is not Foundation-ready. `package.json` exposes no `bin`, `tools/tiinex-portable.mjs` has a Node shebang but is not executable in the carried source mode, help presents `node tools/tiinex-portable.mjs ...`, and ordinary Handoff manufacture still requires multiple internal paths/ids/flags that encourage humans and LLMs to construct wrapper scripts.
- Next Tranche: Loom may enter the two remaining inherited oversized owners, `src/tooling/portable/adapters/cli/cli.run.js` and `src/tooling/portable/handoff/carrierProjection.js`, plus the minimal package/entrypoint/help/support files needed to make one human-first command surface coherent.
- Human-First Objective: provide a normal `tiinex` command surface that does not require callers to prefix Node or know internal module paths. A package `bin`/installed executable backed by Node is sufficient; a native binary is not required.
- Discoverability Objective: `tiinex --help` should make ordinary orientation, bounded validation, and Handoff receive/return/manufacture flows discoverable without dumping the implementation operation catalog as the only useful entrypoint. Existing exact portable operations must remain available for advanced and machine use.
- Defaults Objective: the normal path should infer already-qualified workspace identity, target, route, parent-carrier continuity, and projected output where exact and unambiguous; ambiguous or missing authority must fail closed or request explicit input rather than guessing.
- Carrier UX Objective: preserve carrier dimension as convenience progress/retention data while making the human filename/output projection non-misleading. The current `site-001-001-...` shape can visually resemble duplicated semantic majors even though workspace id and carrier dimension are separate and non-authoritative; Loom may simplify or disambiguate that projection without changing carrier semantic authority.
- Test Discipline: preserve one permanent `*.test.mjs` acceptance entrypoint plus 54 suite-owned `*.case.mjs` current-contract cases. Add or adjust coverage inside existing suite ownership; do not create standalone regression/unit/acceptance test files.
- Host Observation Boundary: checkpoint occurrence and worked time remain separate observations. Do not infer hidden host scanning, classifier thresholds, trigger keywords, telemetry, or bypass mechanics from timing or execution shape.

- Current Tooling source already states `authority: human-progress-projection-only` for carrier lineage and a boundary that carrier lineage never replaces artifact lineage or source/Handoff truth. The cold-start continuation projection independently states that return carrier lineage is a human progress/retention projection only.
- The remaining strict-static owners are exactly `cli.run.js` at 42,844 bytes and `carrierProjection.js` at 33,356 bytes, and both sit directly on the command/human transport surface now under review.
- `tools/tiinex-portable.mjs` already has a `#!/usr/bin/env node` entrypoint, so a thin executable/package-bin front door can reuse the current runtime rather than introduce a new runtime architecture.

- Existing exact operation names and JSON result contracts remain available; friendly verbs/defaults are a convenience layer, not a replacement semantic authority.
- Carrier filename/dimension changes are projection-only. Do not alter artifact lineages, Handoff meaning, Workspace ids, or semantic Parent/Trace/Origin to make filenames prettier.
- Permanent acceptance must remain 54/54, focused/tooling must remain 4/4 with zero introduced static regressions, and relevant manufacture/orientation/cold-start/carrier-lineage cases must remain green.
- A representative fresh-shell/local-install or equivalent executable-path check should demonstrate that a human can discover and invoke the normal Tiinex CLI without writing a wrapper and without typing a Node prefix.
- Broad integration, strict closure, release, publication, and Foundation stable qualification remain outside Loom's bounded implementation turn and return to Anchor for the next checkpoint.
