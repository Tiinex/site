# Fresh Zero-Precontext Common CLI Acceptance — Anchor To Loom

## Handoff Parties

- Purpose: test the current carried Tooling exactly as a genuinely new model context would encounter it, without prior Loom conversation memory, and return bounded acceptance evidence without modifying implementation during the test
- From: Anchor
- From Kind: role
- From Reference: [Anchor Role](business::.topics/roles/001-1-anchor-role.trace.md)
- To: Loom
- To Kind: role
- To Reference: [Loom Role](business::.topics/roles/001-3-loom-role.trace.md)

## Transfers

- zero-precontext-cold-acceptance
  - Transfer Kind: work-and-responsibility
  - Description: start in a brand-new Loom conversation with no prior Tiinex chat context beyond this carrier and the normal cold-start routing text; qualify bootstrap/orientation and use the one public `ground` path to determine whether the model can become correctly grounded without relying on hidden conversational memory
  - Boundary: package cold start inside an already warm role conversation does not satisfy this gate

- continuity-to-root-proof
  - Transfer Kind: work-and-responsibility
  - Description: require cold-start act-readiness to prove required declared Parent continuity to a qualified semantic root or to carry an independently valid compact proof; when an exact required Parent is absent locally, follow Tooling's bounded exact host-recovery projection and keep FETCHED != VERIFIED
  - Boundary: do not use filename dimensions, carrier dimensions, search-based ancestry, semantically similar replacements, or remembered prior context as Parent authority

- common-cli-no-glue-acceptance
  - Transfer Kind: work-and-responsibility
  - Description: evaluate whether the taught happy path remains one `ground` command plus a simple exact host-tool binding, one explicit Tooling-owned state path, and raw fetched UTF-8 host-result return; internal request/plan/receipt/prior JSON and custom Python/Node glue must not become necessary common-path knowledge
  - Boundary: diagnostic escape hatches may exist but using them because the public route cannot proceed is an acceptance failure to report, not something to normalize

- host-capability-recovery
  - Transfer Kind: work-and-responsibility
  - Description: if Tooling projects an exact repository/ref/path host action and the host exposes the matching connector, execute only that exact action and return the fetched material through the supported common continuation surface; if no bounded host capability exists, stop and request exact Transport Operator material instead of guessing
  - Boundary: Tooling cannot silently invoke the host connector from its local sandbox and connector exercise grants no semantic authority by provider name

- bounded-return-evidence
  - Transfer Kind: work-and-responsibility
  - Description: return concise evidence of the actual cold path, including whether full required continuity reached a qualified root, which public CLI concepts had to be understood, whether any improvised glue was required, whether operator escalation was needed, and the final grounded/degraded/blocked state
  - Boundary: this tranche is an acceptance observation, not an implementation turn

## Completion Expectation

- Signal Kind: result
- Signal Meaning: a genuinely brand-new zero-precontext Loom conversation returns one canonical child carrier proving either (a) the isolated common CLI can cold-start, recover every required missing Parent through bounded host actions or explicit operator fallback, qualify continuity to a semantic root, and reach the correct final grounding state without internal protocol glue, or (b) the exact point where that acceptance fails, without modifying the implementation under test
- Return To: Anchor
- Return To Reference: [Anchor Role](business::.topics/roles/001-1-anchor-role.trace.md)

## Interpretation Limits

- Does Not Mean: Sigma final CLI acceptance, Viewer readiness, Chrome Extension readiness, release qualification, remote publication, carrier-major promotion, or general autonomous-agent readiness
- Must Not Be Used To Claim: warm-role memory as cold evidence, Work/persistent-host behavior as baseline evidence, connector provider identity as semantic authority, missing lineage as harmless, or a test-time patch as proof the tested version passed
- Authority Limits: Loom owns only the fresh acceptance execution/evidence; Anchor retains architecture/progression; Sigma retains human quality authority; Axiom retains canonical semantics; Transport Operator remains the final exact-material fallback
