# Fresh Zero-Precontext Human-First CLI Output-Density Acceptance

## Objective

Independently test the corrected carried Tooling as a genuinely fresh zero-precontext Loom consumer and determine whether the ordinary shared CLI is now both technically no-glue and practically bounded enough for human/LLM use.

## Scope

- Use the exact incoming carrier and declared cold-start bootstrap path.
- After Tooling takeover, use the same public CLI surface a human would use; do not write bespoke Python, shell parsing/glue, JSON-navigation code, native Workspace ZIP extraction, or alternate Tiinex protocol helpers for the normal path.
- Exercise the ordinary `orient`, `ground`, `ground --continue`, bounded task inspection/continuation, `author`, and `handoff` path needed to return acceptance Evidence.
- Deliberately request full detail only when verification requires it; record whether the compact default itself supplies the next action and decision-critical state.

## Acceptance Invariants

- One public CLI surface for human and LLM; no special LLM façade.
- Default output is deterministic, bounded, and immediately legible enough to identify readiness, Role/authority, current work, Required Context closure, continuity/blockers, materialization result, and exact next action without receipt archaeology.
- `--full` remains available on the same commands and retains qualified evidence when deliberately requested.
- Blocked/degraded state remains fail-visible; compact rendering must never create false green.
- No bespoke post-takeover Tiinex glue is required on the normal path.
- Author/handoff return path remains usable and qualified.

## Required Observations

- Record wall-clock host time as an observation only; do not infer Tooling causality from it.
- Record raw output size/line count for the ordinary default `orient`, `ground`, and `ground --continue` calls when practical.
- Note any point where the fresh consumer feels compelled to inspect internal receipts, write glue, or guess the next command.

## Required Context

- Anchor candidate decision for the output-density correction.
- Loom final output-density correction Evidence.
- Sigma human-first CLI output-cost Feedback.
- Carrier-major `006` adversarial grounding/recovery acceptance baseline.

## Dependencies

- The Anchor candidate decision and Loom final correction Evidence are available in the carried Site Workspace and define the exact candidate under test.
- Carrier-major `006` acceptance remains the fail-closed grounding/recovery baseline.
- Sigma output-cost Feedback remains the human-observed acceptance boundary; fresh Loom may report behavior but may not fabricate Sigma judgment.
- If the fresh run reproduces a defect that requires source mutation, keep the correction bounded and return explicit RCA/evidence; otherwise do not mutate the candidate.

## Exclusions

- No source redesign unless a reproduced acceptance failure requires a bounded correction; if so, return the failure and minimum RCA rather than silently broadening scope.
- No package-topology redesign, sibling-carrier work, Viewer, Chrome Extension, semi-automation, commit, push, release, deployment, or remote mutation.
- Do not self-accept carrier-major `007`; Anchor/Sigma retain that gate.

## Done Criteria

- Fresh zero-precontext run completes or fails visibly with exact evidence.
- Technical no-glue and output-density/human-recognizability are reported separately.
- Focused/Foundation regressions are rerun if source changes occur; unchanged-source acceptance may rely on the carried qualified baseline plus targeted verification.
- Return qualified Evidence and one canonical full-source Business+Docs+Site carrier to Anchor.
