## Accepted Source Boundary

- Authored artifact `id` and `path` remain authored identity and are not prefixed with host roots for collision avoidance.

- `loadedSourceBasis` is projection-only consumer evidence and does not replace Parent, Origin, Source, Workspace, Relation, or publication semantics.
- Same-path material from separate explicit roots may remain distinguishable by locator while retaining the same authored path.
- Repository identity and public permalink remain unavailable unless separately supplied and qualified.

## Post-Acceptance Discovery

- The existing host receipt path already normalizes explicit repository-read material with `repository`, `ref`, `commit`, `path`, `authority`, `remoteFetch`, and source mode `portable-host-repository`.
- The current portable input path recognizes non-local supplied source primarily through `source.adapterId`; accepted host-repository source objects do not use that shape and can therefore lose their repository/ref/commit facts when passed onward.
- This is a Tooling composition gap between already-existing receipt normalization and already-existing loaded-source projection. It does not justify new Source, Project, Workspace, Discovery, or overview schemas.

## Next Tooling Authorization

- Inspect and reuse the existing `accept-host-receipt` repository material shape and portable input/provider-response contracts before adding any new abstraction.
- Preserve explicit repository/ref/commit/path/authority facts from already-accepted repository-read receipts through provider-neutral portable normalization.
- Keep the distinction between pinned and moving-ref material explicit. A missing commit must not become durable repository identity or a stable permalink claim.
- Allow Operating Overview to expose the smallest useful qualified repository source basis only when that qualification is actually present from the accepted Tooling receipt path.
- Unverified generic source metadata, local paths, archive entries, filenames, and nearby Workspace declarations must remain non-authoritative and must not be promoted merely because they look repository-like.
- Prefer projecting an explicitly supplied durable locator/permalink when one is already part of qualified receipt material. Do not synthesize public URLs in this tranche unless an existing shared Tooling contract already owns that derivation.
- Add adversarial proof that pinned accepted repository material retains its explicit repository/commit/path basis, unpinned material remains visibly moving-ref/non-durable, and lookalike unverified metadata cannot gain stronger qualification by shape alone.
- Preserve the accepted Operating Overview semantics and all 21 portable Handoff tests.

## Stop Conditions

- Stop before performing network fetch, repository crawling, Monitoring freshness, Viewer integration, Business mutation, or Docs mutation.
- Stop before inventing canonical provenance or publication authority from a host receipt.
- Stop before changing Source, Workspace, Relation, Project, Task, Monitoring, Parent, Origin, or Discovery schema semantics.
- Return to Anchor/Axiom if trustworthy qualification requires a new semantic authority rather than composing existing Tooling receipt evidence.
