# Tranche C Adversarial Recovery Integrity Acceptance

## Decision

Anchor accepts the returned Tranche C implementation and evidence as a qualified correction to the carrier-major 005 isolated-LLM Tooling baseline. Five adversarial recovery-integrity cases passed without source changes; one exact repository-read receipt identity-binding defect was reproduced, root-caused, minimally corrected, and permanently regressed. Carrier major 006 is not yet authorized: one independent fresh zero-precontext acceptance run remains the next gate.

## Basis

- The received `005-1-1` routed carrier qualified through the declared bootstrap, exact Handoff Pointer, all four Required Context items, selected-route Parent lineage, and cold-start continuity proof to a qualified semantic root.
- Loom reproduced one concrete failure: a repository-read receipt could return mismatched repository, path, and ref/commit identity and still be admitted as candidate material.
- Loom established the owning layer and violated invariant before changing source: exact host recovery may admit only bytes bound to the concrete planned target identity.
- The minimum correction binds normalized repository-read receipt files to the planned repository, normalized path, and requested ref/resolved commit identity, excludes mismatches, and retains FETCHED as distinct from VERIFIED.
- A permanent regression covers the reproduced mismatch; the final six-case adversarial probe passed 6/6, focused/tooling passed 4/4 with inherited=0 and introduced=0 static debt, and Foundation passed 55/55.
- No canonical semantic-contract contradiction was reported, so no Axiom escalation is required for this tranche.

## Consequences

- The corrected Site source becomes the candidate adversarial-grounding baseline for an independent fresh-cold acceptance run.
- The next run must be performed by a brand-new zero-precontext Loom in ordinary Chat/sandbox conditions, using the same public Tiinex CLI common path as a human.
- The fresh run is acceptance-only: it should not modify Tooling source to make the gate pass. Any reproduced defect must be returned to Anchor as failure evidence for a new bounded implementation tranche.
- The fresh run must preserve the post-bootstrap ergonomics boundary: no custom Python, hand-built request/receipt JSON, native ZIP archaeology, or bespoke parsing is part of the normal Tiinex path after Tooling takeover.
- Carrier major 006 remains blocked until Anchor receives and qualifies that independent fresh-cold acceptance result.
