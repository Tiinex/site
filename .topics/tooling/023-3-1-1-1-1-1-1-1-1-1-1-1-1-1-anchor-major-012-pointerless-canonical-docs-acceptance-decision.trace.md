# Major 012 Pointerless Carrier Canonical Follow-Through — Anchor Reconciliation

Anchor accepts Axiom's maintained Docs materialization of the already-approved two-mode `tiinex.handoff.package.v1` contract. The canonical change is bounded to one existing schema file and preserves ordinary Handoff-route behavior while adding the explicit pointerless complete-Workspace carrier mode.

## Decision

- State: accepted-canonical-follow-through
- Subject: Major 012 pointerless Handoff Package carrier semantics
- Decision: accept the carried canonical Docs result where `Package Role` has exactly the two closed values `recipient-facing-handoff-carrier` and `recipient-facing-workspace-carrier`; ordinary Handoff-carrier mode retains its exact route triplet, while Workspace-carrier mode requires the exact all-`none` Route Discovery triplet.
- Operative Effect: the deliberate Site Tooling blocker `portable.handoff-package-v1.workspace-carrier.canonical-follow-through-required` is now obsolete for this qualified carried Docs authority and should be removed/reconciled by Loom. Pointerless manufacture may become executable only when the implementation validates the accepted Workspace-carrier rules and preserves fail-closed ordinary Handoff-carrier behavior.

## Basis

- The corrected Axiom return carrier qualifies cleanly across Business, Docs, Site, and vscode and grounds to act under explicit Anchor holder-role binding.
- Axiom's exact baseline/current Docs comparison reports one modified canonical file, zero additions, zero deletions, with resulting raw SHA-256 `d43f0f65894a32a9edab04f9dc30eb5562f8025018e88f2121857803f3f83f38` and verified c14n-v2 self seal.
- The maintained contract explicitly makes Workspace-carrier mode pointerless: `Route Placement Rule: none`, `Continue-From Rule: none`, and `Pre-Handoff Closure Rule: none`; mixed triplets fail closed and `none` cannot be reinterpreted as unknown, implicit, deferred, or later-inferred Handoff selection.
- Workspace-carrier mode explicitly does not create or infer From/To, recipient capacity, Role holder, current Task/current Workspace, transfer, acceptance, completion, participation, or continuation semantics from package membership or surrounding transport context.
- Existing Handoff-carrier mode remains unchanged and continues to require the exact selected-route profile and qualified Handoff Pointer behavior.

## Consequences

- Loom may remove the temporary canonical-follow-through blocker from shared Site Tooling and update permanent regressions so pointerless Workspace-carrier manufacture is executable and qualified against the carried canonical Docs bytes.
- The native `Tiinex/vscode` package builder must expose `No Handoff pointer` as an explicit choice and route that choice through the same shared manufacture path rather than host-local ZIP semantics.
- Pointerless manufacture remains a Workspace carrier, not a Handoff. No endpoint, Role, current-work, acceptance, completion, or transfer semantics may be synthesized by VS Code or shared Tooling.
- A successful implementation return should include an installable deterministic VSIX candidate and exact technical qualification sufficient for one bounded Sigma dogfood turn.

## Review Conditions

- Ordinary Handoff-carrier manufacture and exact route qualification remain backward-compatible.
- Workspace-carrier mode emits no selected package-local Handoff Pointer route and fails closed if Handoff-route selection is supplied or if Workspace qualification is incomplete.
- No third carrier mode, remote publication, marketplace release, automatic Git mutation beyond already accepted operator policy, Viewer parity, Playthings synchronization, or Major 012 closure is authorized here.
- Major 012 remains open through one bounded Sigma human dogfood/reconciliation turn after Loom's unblock return.
