# Human-First Common CLI — Tranche A

## Objective

Make the ordinary Tiinex public CLI feel like one small human-first tool rather than an internal operation catalog, while preserving the exact same commands, defaults, and output contracts for humans and LLMs.

The first obligation is evidence, not redesign: reproduce the remaining common-path friction from carrier major `006`, identify its owning layer/root cause, and only then apply the smallest shared Tooling correction justified by that evidence.

## Acceptance Target

A new ordinary consumer should be able to discover and complete the bounded Tiinex lifecycle through one public surface:

1. receive/orient and ground the exact routed carrier;
2. continue into the exact current Task and Required Context without bespoke parsing or archive work;
3. author a qualified result on the same public CLI path;
4. produce the canonical return Handoff/carrier on that same path;
5. discover advanced/internal operations only when deliberately asking for them.

The CLI must not teach a special LLM route. Human and LLM usage is one route.

## Scope

- Public common-path CLI discoverability and orchestration from the accepted carrier-major `006` baseline.
- Shared portable Tooling implementation and permanent regression coverage only where reproduced evidence justifies it.
- Fresh ordinary human/LLM usability is evaluated against the same command surface and output contracts.

## Work

- Establish an unchanged-source baseline for current `006` common-path behavior, public `--help`, focused Tooling regression profile, and Foundation acceptance.
- Reproduce concrete discoverability or orchestration friction before changing shared source. Record symptom, minimal reproduction, owning layer, root cause, violated invariant, and why the proposed correction is minimal.
- Treat the current common-path operations (`ground`, `author`, `handoff`, and any already-qualified orientation/inspection behavior they require) as the starting surface, not as permission to create a second façade.
- Prefer use-case-first public help and progressive disclosure. Internal/diagnostic operation vocabulary may remain available behind the existing advanced catalog, but ordinary help should not require a consumer to understand that catalog.
- Preserve the accepted carrier-major `006` grounding/recovery invariants, exact Parent continuity, fail-closed recovery, `FETCHED != VERIFIED`, host-recovery identity binding, and post-takeover no-glue boundary.
- Add permanent regression coverage only for a general invariant exposed by a reproduced defect; do not accumulate historical one-off tests.
- Return Loom implementation/evaluation Evidence and a Tooling-manufactured full-source Business+Docs+Site child carrier to Anchor.

## Human-First Invariants

- One CLI surface. No human CLI plus LLM CLI split.
- Same commands, defaults, and output contracts for human and LLM consumers.
- Normal use should be understandable from the public surface without reading internal operation names or hand-building Tooling protocols.
- `ground --continue` remains responsible for ordinary current-context/source materialization after takeover.
- `author` remains responsible for ordinary result artifact continuity/integrity/validation staging rather than asking the caller to recreate those mechanics.
- `handoff` remains responsible for ordinary canonical return-carrier inference/manufacture rather than asking the caller to reconstruct package topology.
- Advanced/debug escape hatches may exist, but must not become the happy path.

## Root-Cause Discipline

For each claimed defect or friction point:

`observed symptom → minimal reproduction → owning layer → root cause → violated invariant → minimum correction → regression/acceptance evidence`.

Do not implement a guessed feature merely because a hypothetical consumer might need it.

## Exclusions

- No Viewer feature work.
- No Chrome Extension/Host Bridge implementation or semi-automation.
- No release/deployment/remote mutation.
- No schema-semantic redesign unless a concrete contradiction requires Axiom review.
- No new Handoff package artifact kinds or package grammar/topology changes without explicit Sigma approval.
- No reopening of closed adversarial grounding/recovery work absent reproduced contradiction.

## Dependencies

- Carrier-major `006` adversarial grounding/recovery acceptance is the stable baseline.
- Sigma's existing common-path ergonomics feedback remains a controlling human observation: ordinary post-takeover Tiinex use must not require bespoke navigation/protocol glue.
- Existing authoring/return common-path work is baseline capability, not evidence that broader human discoverability is already accepted.

## Done Criteria

- Remaining bounded common-path friction is either reproduced and root-caused or explicitly shown not to reproduce on the accepted baseline.
- Any shared Tooling change is the minimum correction justified by the reproduced invariant, with no second human/LLM interface.
- Ordinary public help presents the common lifecycle before advanced/internal operation vocabulary, and deliberate advanced discovery remains available separately.
- Focused Tooling regression profile and Foundation acceptance pass without new structural/static debt attributable to this tranche.
- The accepted `006` grounding/recovery/no-glue invariants remain green.
- Loom returns durable implementation/evaluation Evidence and a Tooling-manufactured full-source Business+Docs+Site child carrier to Anchor.

## Completion

Return to Anchor with:

- exact reproduced friction/root-cause evidence (or explicit evidence that the bounded surface already meets the target unchanged);
- minimal shared Tooling changes, if justified;
- focused Tooling and Foundation results;
- a concise statement of what remains outside this tranche;
- canonical full-source return carrier.
