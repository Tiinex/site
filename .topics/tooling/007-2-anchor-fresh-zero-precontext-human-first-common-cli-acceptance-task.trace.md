# Fresh Zero-Precontext Human-First Common CLI Acceptance

## Objective

Independently accept or reject the corrected Human-First Common CLI Tranche A candidate in a brand-new zero-precontext Loom conversation using the exact same public Tiinex CLI surface intended for ordinary humans and LLMs.

This is an acceptance/evaluation tranche, not an implementation tranche. Do not modify shared Tooling source unless a reproduced acceptance blocker is first isolated and Anchor explicitly authorizes a correction in a later handoff.

## Scope

- Fresh zero-precontext acceptance/evaluation of the corrected Tranche A public CLI candidate only.
- Read-only grounding/orientation behavior plus ordinary local acceptance Evidence authoring and canonical return-carrier manufacture through the shared Tiinex CLI.
- No shared Tooling source mutation is authorized in this tranche.

## Acceptance Target

Starting only from the received carrier and its declared Start/bootstrap contract, a fresh Loom must be able to:

1. reach Tiinex takeover with only the authorized minimal pre-takeover bootstrap action;
2. discover the ordinary lifecycle from public `--help` without receiving the advanced/internal operation catalog by default;
3. `ground` the exact routed carrier and become correctly `grounded-to-act`;
4. `ground --continue` into the exact current Task and Required Context without bespoke package, JSON, parser, search, or protocol glue;
5. interpret grounding operation safety as operation-scoped and not as a false revocation of separately qualified downstream Task/Handoff authority;
6. use the public `author` and `handoff` common path to preserve the acceptance result and manufacture the canonical full-source return carrier;
7. use no second LLM-only façade, hidden prior conversation context, or connected-host magic for correctness.

## Fresh-Cold Conditions

- `🧊 FRESH COLD ROLE REQUIRED`: use a brand-new Loom conversation with zero Tiinex pre-context from earlier Loom threads.
- Ordinary Chat/isolation remains the baseline; ChatGPT Work or persistent workspace context is not required.
- Before Tiinex takeover, the Start-authorized minimal native bootstrap read/verification/extraction is allowed.
- After Tiinex takeover, invoking the Tiinex CLI through the host shell is allowed.
- After takeover, bespoke Python/shell glue for archive archaeology, JSON interpretation, lineage navigation, protocol assembly, or workspace extraction is an acceptance failure.
- Ordinary source/text inspection and authoring of the bounded acceptance artifact body are not themselves Tiinex navigation glue.

## Required Observations

### Public help

Record whether default public help:

- presents the common lifecycle (`ground`, `ground --continue`, `author`, `handoff`);
- points to deliberate `operations` discovery;
- does not dump representative advanced/internal operation vocabulary;
- gives focused common-command help for at least `author --help` and `handoff --help`.

### Grounding authority boundary

Record whether a real `ground` receipt:

- remains read-only/fail-closed for the grounding operation;
- scopes source/remote mutation facts to the current grounding operation;
- clearly preserves Handoff/Task/Role authority over separately authorized downstream work;
- does not lead the fresh consumer to infer that all local downstream work is prohibited.

### End-to-end common path

Complete the ordinary sequence:

`bootstrap → help → orient/ground → ground --continue → inspect bounded current material → author acceptance Evidence → handoff → canonical return carrier`

No custom Tiinex protocol/receipt construction should be required on the happy path.

## Failure Discipline

If any acceptance target fails:

`observed symptom → minimal reproduction → owning layer if knowable from qualified evidence → acceptance impact`

Do not guess a feature or patch shared source in this tranche. Return a failing acceptance Evidence/carrier to Anchor.

## Required Context

- Loom correction Evidence proving the reproduced defects, owning layers, minimum corrections, and green focused/Foundation validation.
- Anchor correction authorization Decision establishing the bounded semantic/source-work distinction.
- Human-First Common CLI Tranche A controlling Task.
- Carrier-major `006` acceptance baseline.
- Sigma common-path ergonomics feedback requiring one ordinary post-takeover route without bespoke navigation/protocol glue.

## Dependencies

- The carried Loom correction Evidence is the implementation/evaluation candidate under review.
- The Anchor correction authorization Decision defines the source-work versus grounding-operation-safety boundary.
- The controlling Human-First Common CLI Tranche A Task defines the one-surface and no-glue invariants.
- Carrier-major `006` acceptance remains the stable grounding/recovery baseline.
- Sigma common-path ergonomics feedback remains controlling human evidence for the post-takeover no-bespoke-glue boundary.

## Exclusions

- No shared Tooling source changes in this acceptance tranche.
- No Viewer, Chrome Extension/Host Bridge, semi-automation, release/deployment, commit, push, or remote mutation.
- No schema/package-topology redesign.
- No carrier-major `007` acceptance claim; Anchor retains that progression decision.
- Do not fabricate Sigma human acceptance.

## Done Criteria

- Fresh-cold conditions are explicitly satisfied or a blocker is reported.
- Public-help progressive disclosure is observed on the actual corrected CLI.
- The grounding operation-authority boundary is correctly understood from actual output.
- The normal post-takeover path completes without bespoke Tiinex navigation/protocol glue.
- `author` and `handoff` manufacture a qualified canonical return carrier.
- Durable Loom acceptance Evidence records pass/fail, exact relevant observations, any workaround count, and retained limits.
- Return one canonical full-source Business+Docs+Site child carrier to Anchor.

## Completion

Return to Anchor with a qualified Loom acceptance Evidence and canonical carrier. A clean pass makes the candidate eligible for Anchor review and a later explicit Sigma human-recognizability gate before carrier-major `007`; it does not itself accept that major.
