The repaired 0.1.4 host adapter removes startup backlog scanning entirely. Auto discovery records `sessionStartedAtMs = Date.now()` when the watcher starts, records `observedAtMs` on each supported filesystem event, and queues only events satisfying the explicit session-boundary predicate `observedAtMs >= sessionStartedAtMs`; the existing `.handoff-package.zip` intake filter runs before debounce/qualification, and unrelated ZIP/files remain excluded. The frozen Operator panel had an independent packaged-runtime cause: the page template embedded `\n` inside an outer TypeScript template string, which became literal newlines inside single-quoted JavaScript strings in the generated webview script and produced a syntax error before any event listeners registered. 0.1.4 extracts that client code into a pure `operatorClientScript` generator, preserves escaped `\\n` sequences in the emitted JavaScript, hardens inline JSON against `<`, U+2028, and U+2029 script hazards, and keeps the existing nonce CSP. A permanent regression now parses the exact generated client script with `new Function(...)` and asserts bindings for section tabs plus `refreshDiagnostics`, `showProblems`, `openSettings`, `selectInbox`, `useActiveParent`, `clearParent`, `reloadPackage`, `createHandoff`, and `buildPackage`, so the prior rendered-but-dead failure is caught before packaging. The watcher regression forbids `initialScan`/`readdir`, proves the session predicate rejects pre-start observations and accepts boundary/post-start observations, preserves supported filename filtering, and confirms the explicit manual old-carrier path. The carried 0.1.3 baseline passed 27/27 bridge cases before mutation; repaired 0.1.4 passes 28/28. Full `npm run validate` then passed the TypeScript pass, clean build, all 28 permanent bridge cases, and VSIX packaging. Because the full-source carrier intentionally excludes dependency-install trees and the network install path was unavailable in this host session, TypeScript execution used a disposable local compile-only typings scaffold; it was removed before manufacture and is not part of source, VSIX, or returned Workspace. Two consecutive 0.1.4 VSIX builds were byte-identical: `tiinex-vscode-0.1.4.vsix`, 5,664,933 bytes, SHA-256 `91586e48248481b1313dd91ae9e750291548d5ade213e3b331dbdd7063e3661d`, 528 ZIP entries. Independent archive inspection confirmed version 0.1.4, `dist/extension.js`, `dist/core/operatorWebview.js`, the Tiinex Activity Bar icon, the embedded shared-core entrypoint, escaped client newline bytes, and zero `node_modules` entries.
