  - Transfer Kind: work

- recipient-cli-and-gates
  - Transfer Kind: work
  - Description: make orient/receive/validate/handoff behavior available through the supported human/LLM `tiinex` surface with sane defaults and enforce the lock-candidate pre-send gates before any carrier is exposed to the human transporter
  - Boundary: no ad-hoc wrapper becomes the normal path and generated inventories/receipts remain verification support without semantic authority

- fresh-recipient-roundtrip
  - Transfer Kind: work
  - Description: prove cold Start -> bootstrap -> exact Continue/Handoff Pointer -> package-local ancestor closure -> Role/cache grounding when required -> authoritative Handoff in owning Workspace -> bounded work -> supported return manufacture -> return qualification -> fresh cold recipient using only the returned carrier plus its normal route address
  - Boundary: package emission, checksum success, or sender-side tests alone do not satisfy this transfer
