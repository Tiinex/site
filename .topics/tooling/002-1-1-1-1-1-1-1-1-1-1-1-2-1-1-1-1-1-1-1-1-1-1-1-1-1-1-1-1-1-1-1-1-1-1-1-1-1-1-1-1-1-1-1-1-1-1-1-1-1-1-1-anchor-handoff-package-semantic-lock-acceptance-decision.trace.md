# Handoff Package Semantic Lock Acceptance

## Decision

- State: accepted
- Subject: Foundation recipient-facing Handoff Package semantic grammar before Tooling implementation lock
- Decision: accept Axiom's `tiinex.handoff.package.v1` as the narrow carrier identity/discovery contract and accept its strict complete-only package-local Workspace snapshot binding as the governing semantic shortcut for full Workspace snapshots inside this carrier.
- Workspace Binding: one explicit carried `tiinex.workspace.v1` artifact may bind directly to one exact package-local complete Workspace byte-tree snapshot when the package contract owns the exact member path, SHA-256, complete coverage, safe normalized mapping, and exact Workspace-artifact inner-byte correlation required for receiver requalification.
- Companion Consequence: standalone External Payload plus Workspace Representation companions are not required for that same complete carrier-local Workspace binding when those artifacts would own no independent semantic job. Bootstrap/cache payload descriptors remain External Payload artifacts; generic Workspace Representation remains required for bounded/partial/unknown or independently meaningful representation semantics.
- Discovery Boundary: package-local Parent/path lineage, Workspace placement, cache ancestry, and Role Pointer placement are recipient discovery/grounding only. They do not create source Parent truth, Handoff endpoints/transfers, Required Context meaning, Role participation, delegation, acceptance, Workspace semantic ownership, or authority precedence.
- Role Pointer Boundary: package ancestor Role Pointers remain `tiinex.pointer.v1` grounding prerequisites only. Semantic participation, where present, remains owned by the authoritative Handoff and/or explicit typed Relation.
- Lock State: semantic lock accepted; implementation lock remains pending Loom manufacture/orient/recipient/CLI/gate implementation plus Anchor-qualified fresh-recipient round trip.

## Basis

- Axiom found no maintained Docs authority conflict inside the transferred seam and produced the canonical carried schema at `docs::.topics/.schemas/coordination/handoff/package/tiinex.handoff.package.v1.schema.md`.
- The Axiom result preserves `tiinex.external.payload.v1`, `tiinex.workspace.representation.v1`, `tiinex.handoff.v1`, `tiinex.pointer.v1`, Root Parent/Origin, Role authority, and `tiinex.semantic.package.v1` without overloading their current jobs.
- Parent Anchor's grounding correction is now explicit in the carried Site lock candidate and in the accepted package schema rather than depending on chat context.
- The Axiom return carrier itself still uses the currently implemented companion transport representation; that implementation lag is evidence for the Loom lane, not a contradiction in the accepted semantic result.

## Consequences

- Loom may implement the accepted minimal package grammar and remove redundant per-Workspace payload/representation companions only for qualifying complete package-local bindings.
- Loom must preserve bootstrap/cache External Payload ownership, numeric package dimensions, one-major carrier projection, owning-Workspace route placement, selected-pointer ancestor closure, bounded cache behavior, full Business/Docs/Site Foundation carriage, no receipt authority, and the supported human/LLM CLI front door.
- Loom must not introduce `participantRolePointers` as semantic authority, infer participant meaning from package placement/order, broaden Role/Handoff/Relation schemas, or open a generic transport ontology.
- Loom must prove cold Start -> bootstrap -> exact route -> ancestor closure -> authoritative Handoff -> bounded work -> supported manufacture -> qualified return -> fresh cold recipient before Anchor can call the Handoff Package implementation locked.
- Axiom is reopened only if Loom demonstrates a concrete maintained-schema conflict that cannot be solved inside this accepted contract.
