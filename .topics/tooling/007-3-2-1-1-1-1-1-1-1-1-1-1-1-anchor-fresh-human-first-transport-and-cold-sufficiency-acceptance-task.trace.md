# Fresh Human-First Transport And Cold-Sufficiency Acceptance

## Objective

Run one genuinely fresh zero-precontext acceptance of the corrected shared Tiinex public path, with the human-facing transport surface itself treated as part of the test.

## Acceptance Setup

- Use a new Loom conversation with no useful prior Tiinex conversation context.
- Begin only from the exact returned Handoff package and its declared Start/bootstrap contract.
- Use a new empty receiver Workspace/output directory.
- Do not rely on inherited `.tiinex/continuation.json`, pre-materialized Workspace state, useful ambient cache, or hidden host memory for correctness.
- After the bootstrap exception, use the ordinary public Tiinex path; do not hand-parse package ZIPs, receipts, or continuation state.

## Observe The Common Path

Exercise the ordinary public lifecycle needed to receive, understand, act on, and return this bounded acceptance result.

Record, without over-instrumenting the run:

- whether ordinary output is recognizable and materially bounded,
- whether exact next actions are clear without receipt archaeology,
- whether the normal completion surface is exactly one Handoff package plus adjacent copyable routing text,
- whether a markdown-capable host presents that routing as a fenced code block,
- whether loose Evidence/Handoff markdown appears as extra transport payloads,
- whether cache/runtime state is visibly non-authoritative and correctness survives empty prior state,
- whether any bespoke post-takeover Tiinex glue is required.

## Technical Gate

A technical pass requires:

- `orient`/`ground`/`ground --continue` remain qualified and fail-visible,
- empty-Workspace/no-prior-cache cold correctness remains intact,
- public author/handoff lifecycle can return a qualified carrier,
- normal transport projects one canonical Handoff package only,
- routing text is short and copyable,
- no second human/LLM CLI surface is introduced,
- carrier-major 006 grounding/recovery invariants remain intact.

## Human Gate

Do not fabricate Sigma acceptance. Loom may report observed behavior and technical qualification only. Sigma retains the final judgment on whether the shared CLI/transport experience is sufficiently human-first for carrier-major 007.

## Scope

This is an acceptance run, not an implementation tranche. Do not mutate Tooling source merely to polish the test. If a blocker or regression appears, preserve exact Evidence and return it to Anchor rather than broadening scope.

Retain the separate carrier side-track rule as context only: serial depth is default; breadth is intentional; explicit ancestor sibling branching is an escape hatch, not a response to long paths.

## Dependencies

- Loom final human-first transport/cold-sufficiency Evidence and return Handoff are the technical baseline for this acceptance.
- Sigma retains final human workflow acceptance; this run may not self-grant that decision.
- Carrier-major 006 adversarial grounding/recovery acceptance remains the fail-closed safety baseline.
- If host presentation differs from the declared one-carrier/fenced-routing contract, return the exact deviation rather than inventing a host-specific protocol.

## Exclusions

- No Viewer, Extension, Host Bridge, semi-automation, release, deployment, commit, push, or remote mutation.
- No schema/package semantic redesign.
- No carrier-major 007 self-acceptance.

## Done Criteria

Return qualified Evidence and one canonical Loom-to-Anchor Handoff package describing the fresh run, its technical status, any transport/presentation deviations, and the explicit boundary that Sigma retains final human acceptance.
