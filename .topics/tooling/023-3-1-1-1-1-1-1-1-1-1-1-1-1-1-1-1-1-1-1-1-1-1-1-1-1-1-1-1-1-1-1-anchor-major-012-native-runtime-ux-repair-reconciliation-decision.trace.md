# Major 012 Native Runtime UX Repair — Anchor Reconciliation

Anchor accepts Loom's 0.1.2 native runtime UX repair as the technically qualified candidate for the next bounded Sigma dogfood. This decision does not close Major 012 and does not authorize repository publication or Marketplace release.

## Decision

- State: accepted-for-human-dogfood
- Subject: Tiinex/vscode 0.1.2 native runtime UX repair
- Decision: accept the returned `Tiinex/vscode` 0.1.2 candidate as the current technical basis for human actual-path observation. Preserve VS Code as a thin host adapter over shared Tiinex Tooling and route the exact installable candidate to Sigma for natural dogfood before any Major 012 closure decision.
- Operative Effect: Sigma may install and naturally use the 0.1.2 VSIX. Anchor will reconcile the resulting human observations and either close the bounded UX gap, route one more bounded repair, or withhold closure if actual-path behavior remains materially broken.

## Basis

- The Loom return carrier qualifies all four carried Workspaces and reaches `grounded-to-act` under explicit Anchor holder-role binding with no blockers.
- Loom preserves technical Evidence for a clean 0.1.1 baseline at 20/20 bridge cases and a repaired 0.1.2 candidate at 25/25 permanent bridge cases plus the full `npm run validate` spine.
- The exact installable candidate is `dist/tiinex-vscode-0.1.2.vsix`, 5,606,078 bytes, SHA-256 `bfc3e943740bfef71acdf8269a836cd4bc7f6e157694c54c71ac70bf0acd8c6b`.
- The repair moves diagnostics toward ordinary native VS Code behavior: eligible Markdown is validated automatically on open, debounced in-memory change, and save/requalification through the shared `project-editor-assistance` operation; VS Code retains only scheduling, transient byte staging, stale-result guarding, diagnostic projection, Code Actions, and native presentation.
- Handoff authoring now derives safe editable defaults from the explicitly selected Parent, keeps endpoint identity explicit, defaults zero-declaration sections to `none`, and collapses lower-frequency fields.
- Package options load automatically on section activation; discovery exposes explicit `disabled`, `watching`, candidate, error, and confirmation states and requires native `Preview / Land` before the existing fail-closed landing path.
- The Tiinex operator is contributed as an immediately visible Activity Bar container instead of depending on Command Palette discovery.

## Human Dogfood Boundary

- Sigma should judge the natural operator path rather than execute a formal validation matrix.
- Highest-signal surfaces are native diagnostics/Problems/Quick Fix behavior, immediate Tiinex sidebar discoverability, Parent-driven minimal Handoff authoring, Handoff Package building with sane defaults, inbox discovery/notification, and multi-root landing behavior.
- Sigma is not required to commit, push, manually manufacture a return Handoff, or reproduce Loom's technical qualification. Simple observed friction or success is sufficient human evidence.
- Windows remains Sigma's observation host and is not promoted into a universal platform acceptance gate.

## Boundaries

- Major 012 remains open pending reconciliation of this human dogfood.
- This decision does not authorize automatic landing, branch mutation, commit, push, remote repository mutation, VSIX Marketplace publication, release, Viewer parity, Playthings synchronization, deployment repair, destructive Reduction apply, or broader artifact-studio work.
- Shared Site Tooling remains semantic/qualification authority; VS Code must not fork validator selection, severity, source location, repair derivation, Handoff/package semantics, or landing qualification.
