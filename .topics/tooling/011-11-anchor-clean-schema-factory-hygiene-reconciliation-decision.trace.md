# Clean Schema Factory Hygiene Reconciliation

The schema factory is qualified for the next bounded reuse step after removing the loose Evidence inheritance companion from the forward Docs candidate and retaining the same semantics through Root-owned inline `Inheritance Overrides`.

## Decision

- State: accepted for bounded progression
- Subject: schema factory hygiene and next-step readiness
- Decision: keep Docs schema-only by default, retain inline inheritance override authority in canonical child schemas, keep shared compiled descriptors in Site/Tooling, and proceed to one bounded post-factory scale proof without broad catalog fan-out.
- Operative Effect: the loose `tiinex.evidence.v1-preservation-body.inheritance.trace.md` is not part of forward Docs authority; the cleaned Root/Evidence/inheritance schema candidate plus Loom's shared compiler/Viewer implementation is the qualified baseline for the next slice.

## Basis

- Axiom accepted Root-owned inline `Inheritance Overrides` as the canonical schema-local override representation and retained standalone inheritance artifacts only for intentional independent record semantics.
- Loom implemented the representation generically with exact ancestor/node qualification, fail-closed behavior, contributor provenance, no schema-ID branch, and no forward `inheritanceCompanions` dependency.
- Anchor reran factory conformance, Viewer proof, typecheck, UI shape, architecture shape, focused/tooling, integration, and Foundation 63/63 successfully.
- The local Docs candidate now contains only `tiinex.evidence.v1.schema.md` in the Evidence schema directory; Root, Evidence, and standalone inheritance-schema wording are resealed and independently inspect clean.
- Sigma's standing operating instruction authorizes Anchor to continue bounded progression without extra approval turns unless Sigma signals a deviation; this Decision does not claim broad publication or release acceptance.

## Consequences

- Docs remains schema-only by default; optional companion families are not normalized merely because Tooling can generate them.
- `.relations` remains an experimental/maturing candidate outside canonical Docs until its semantics, human value, and representation are proven stable enough for an explicit migration decision.
- Future Schema Builder work must consume and author the same Root-owned inline override primitive and shared descriptor rather than generate helper companion files to make schemas executable.
- The next proving tranche should add useful schemas through the existing factory without introducing new architecture; any semantic gap routes back to Axiom instead of becoming Site/Viewer special-case logic.
