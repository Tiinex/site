# Major 012 Native Validation/Discovery Correctness Repair — Anchor Reconciliation

Anchor accepts Loom's 0.1.3 correctness repair as the current technically qualified basis for another bounded Sigma dogfood. This decision does not close Major 012 and does not authorize publication.

## Decision

- State: accepted-for-human-dogfood
- Subject: Tiinex/vscode 0.1.3 native validation/discovery correctness repair
- Decision: accept the returned 0.1.3 candidate for human actual-path observation. Preserve shared Site Tooling as the authority for schema/currentness/inheritance validation, deterministic diagnostic locations, and repair bytes; VS Code remains a thin host adapter for native Problems/Quick Fix presentation, document lifecycle, inbox discovery, prompts, and existing local Git/landing integration.
- Operative Effect: Sigma may install and naturally use the exact 0.1.3 VSIX. Anchor will reconcile the observed behavior before any Major 012 closure or publication disposition.

## Basis

- The Loom return carrier qualifies Business, Docs, Site, and vscode and reaches `grounded-to-act` under explicit Anchor holder binding with no blockers.
- Loom's qualified Evidence reports Site full validation green, the Foundation acceptance spine 70/70, focused editor-assistance/Handoff mechanics qualification, and VS Code full validation green with 27/27 bridge cases.
- The returned candidate is `dist/tiinex-vscode-0.1.3.vsix`, 5,665,055 bytes, SHA-256 `e1cb2a9f886d47279947c0e497ad977e0658b9569f168e2ccf9a743fb930cbcc`; Anchor independently verified that exact digest and that the embedded extension manifest identifies Tiinex version 0.1.3.
- Shared validation now fails visible when exact historical schema/currentness/inheritance authority cannot be proven instead of confidently applying today's same-ID module. Representative real Business artifacts are reported as withheld/degraded rather than receiving implausible schema-specific errors.
- Shared editor assistance now preserves deterministic locations for projected diagnostics and deterministic c14n-v2 footer hygiene repairs where exact replacement bytes are qualified.
- VS Code now guards unsaved/debounced validation against closed, replaced, or stale documents instead of touching disposed editor state.
- Handoff inbox discovery now performs an initial bounded scan of already-present carriers on Auto activation/restart, retains watcher/debounce handling, exposes explicit discovery states, and still requires explicit Preview/Land confirmation before writes.

## Human Dogfood Boundary

- Existing Activity Bar/sidebar, Parent-driven authoring, package-builder, multi-root, and landing surfaces remain in scope for ordinary usability observation, but this tranche is primarily a correctness repair rather than another redesign.
- No commit, push, publication, formal test matrix, or manually manufactured return Handoff is required from Sigma merely to satisfy this dogfood gate.
