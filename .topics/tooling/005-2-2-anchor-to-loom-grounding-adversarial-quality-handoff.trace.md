# Grounding Reliability Adversarial Quality Tranche B — Anchor To Loom

## Handoff Parties

- Purpose: adversarially qualify and, only where evidence exposes a real gap, harden the accepted shared `ground` path so grounding reliability can be judged as a stable batch before broader common-CLI migration, Sigma human-quality acceptance, or Viewer work
- From: Anchor
- From Kind: role
- From Reference: [Anchor Role](business::.topics/roles/001-1-anchor-role.trace.md)
- To: Loom
- To Kind: role
- To Reference: [Loom Role](business::.topics/roles/001-3-loom-role.trace.md)

## Transfers

- adversarial-grounding-matrix
  - Transfer Kind: work-and-responsibility
  - Description: exercise the accepted grounding-readiness projection against a bounded adversarial matrix covering missing current Task frontier, ambiguous or missing selected-route Parent evidence, incomplete carried Workspace or Required Context closure, Role/authority mismatch, and stale/high-level-only evidence; classify each expected readiness state and prove no false `grounded-to-act`
  - Controlling Artifact: [Grounding Reliability, Common CLI Surface And LLM Ergonomics](005-2-common-cli-surface-and-llm-ergonomics-task.trace.md)
  - Boundary: use the smallest durable invariants under the existing permanent test spine; do not accumulate chat-specific or historically redundant standalone tests

- lineage-dimension-confusion-guard
  - Transfer Kind: work-and-responsibility
  - Description: review the existing Parent-only topology and carrier-lineage guards under deliberately misleading filename/path dimensions, valid carrier progression, malformed carrier dimensions, and major/suffix manufacture inputs; add or refine a regression only where the current suite does not already prove that carrier/path projections cannot become artifact ancestry or semantic authority
  - Controlling Artifact: [Grounding Reliability And Common Path Tranche A — Anchor Acceptance](005-2-1-1-2-anchor-grounding-reliability-common-path-acceptance-decision.trace.md)
  - Boundary: carrier lineage remains human progress/retention projection only; filename/path lineage remains local navigation only; artifact Parent lineage remains semantic ancestry; do not create a new lineage vocabulary or package artifact kind

- bounded-noise-and-scale-probe
  - Transfer Kind: work-and-responsibility
  - Description: exercise grounding with a large irrelevant-artifact field or equivalent generated fixture so the normal decision receipt stays bounded, relevant current pointers remain exact, and the implementation does not require broad body projection merely because total loaded material grows
  - Controlling Artifact: [Grounding Reliability, Common CLI Surface And LLM Ergonomics](005-2-common-cli-surface-and-llm-ergonomics-task.trace.md)
  - Boundary: generated test material may be synthetic and ephemeral; do not add thousands of canonical repository artifacts just to simulate noise

- measure-quality-and-burden
  - Transfer Kind: work-and-responsibility
  - Description: preserve a compact before/after quality receipt including false-green outcomes, false-blocked outcomes, command count for the ordinary common path, emitted bytes/context, Required Context body count, relevant-versus-loaded record burden, and useful phase timing where already supported
  - Controlling Artifact: [Tooling-First Foundation Ergonomics](005-tooling-first-foundation-ergonomics-task.trace.md)
  - Boundary: metrics support bounded quality judgment; do not optimize byte count by hiding blockers, uncertainty, provenance, source boundary, or exact recovery direction

- harden-only-from-evidence
  - Transfer Kind: work-and-responsibility
  - Description: fix only concrete defects exposed by the adversarial matrix, delegating to existing Handoff grounding, context audit, lineage resolver, operating/current-work, carrier lineage, and CLI owners instead of introducing parallel semantic logic
  - Controlling Artifact: [Grounding Reliability And Common Path Tranche A — Anchor Acceptance](005-2-1-1-2-anchor-grounding-reliability-common-path-acceptance-decision.trace.md)
  - Boundary: if a genuine canonical semantic contradiction is discovered, stop that semantic change and return it to Anchor for Axiom routing rather than inventing schema authority in Site

- qualify-return-first
  - Transfer Kind: work-and-responsibility
  - Description: run the applicable focused/tooling regression first, then dependency-independent Foundation, integration, and static qualification; return one canonical full Business+Docs+current-Site child carrier with exact quality evidence before broad CLI migration
  - Controlling Artifact: [Tooling-First Foundation Ergonomics](005-tooling-first-foundation-ergonomics-task.trace.md)
  - Boundary: no Viewer implementation, broad CLI rewrite, strict dependency retry loop, commit/push, publication, or remote mutation in this tranche

## Retained Responsibilities

- architecture-and-progression
  - Retained By: Anchor
  - Responsibility: review Tranche B evidence, decide whether the grounding reliability/quality batch is stable enough for explicit carrier-major promotion, and choose whether the next batch opens broader human-first common-CLI work

- semantic-contradiction-routing
  - Retained By: Anchor
  - Responsibility: route any concrete canonical semantic contradiction to Axiom; absence of a contradiction means no Axiom turn is required

- human-cli-quality
  - Retained By: Sigma
  - Responsibility: judge ordinary human CLI comprehensibility after deterministic common-path behavior is stable; Tranche B may measure machine-visible behavior but does not substitute for Sigma acceptance

- transport-operation
  - Retained By: Transport Operator
  - Responsibility: move the canonical carrier exactly as routed and return the Loom child carrier to Anchor; transport alone does not accept implementation or authorize writes

## Exclusions And Dependencies

- handoff-package-topology-change
  - Kind: excluded-scope
  - Description: recipient-facing Handoff package ZIP/Markdown topology and existing package artifact kinds remain locked; do not add a new package artifact kind or recipient-facing package structure without explicit Sigma approval routed through Anchor

- second-cli-model
  - Kind: excluded-scope
  - Description: humans and LLMs continue to use the same normal `ground` path; do not add LLM-only syntax, hidden aliases, or a competing normal API-shaped CLI vocabulary

- broad-cli-migration
  - Kind: excluded-scope
  - Description: do not migrate the full internal operation catalog in this tranche; adversarially qualify grounding first so the later human-first common CLI rests on stable shared semantics

- viewer-implementation
  - Kind: excluded-scope
  - Description: Viewer remains downstream; do not implement Viewer PoC parity or Viewer-private grounding/lineage/source logic

- schema-semantic-expansion
  - Kind: excluded-scope
  - Description: do not revise canonical Docs schemas unless a concrete contradiction is returned to Anchor and separately routed to Axiom

- remote-mutation
  - Kind: excluded-scope
  - Description: no commit, push, branch mutation, publication, release, or other remote write is authorized by this Handoff

## Completion Expectation

- Signal Kind: return
- Signal Meaning: return one canonical full-source Loom-to-Anchor carrier containing the bounded adversarial grounding-quality matrix, any evidence-backed fixes, explicit false-green/false-blocked results, carrier/path/artifact-lineage confusion safeguards, noise/scale and context-burden measurements, green applicable focused/integration/Foundation/static gates, and explicit unresolved limits; if the batch remains clean enough, Anchor can then judge carrier-major checkpoint readiness
- Return To: Anchor
- Return To Reference: [Anchor Role](business::.topics/roles/001-1-anchor-role.trace.md)

## Interpretation Limits

- Does Not Mean: this tranche must prove every provider/host environment, completes the whole CLI simplification Task, performs Sigma human CLI acceptance, authorizes Viewer work, changes schema authority, changes package topology, qualifies strict release closure, or authorizes remote mutation
- Must Not Be Used To Claim: zero unresolved historical lineage everywhere, that lifecycle status equals lineage position, that carrier/path dimensions encode artifact ancestry, that lower byte count outranks provenance/uncertainty, or that synthetic scale alone proves production performance
- Authority Limits: owning Handoff/Role/Task/Parent and carrier-lineage artifacts/code retain their current authority boundaries; Tranche B qualifies composition behavior and guards, not a new semantic layer
- Transport Limits: successful package delivery or cold start is necessary continuity evidence but does not by itself accept Tranche B or promote carrier major
