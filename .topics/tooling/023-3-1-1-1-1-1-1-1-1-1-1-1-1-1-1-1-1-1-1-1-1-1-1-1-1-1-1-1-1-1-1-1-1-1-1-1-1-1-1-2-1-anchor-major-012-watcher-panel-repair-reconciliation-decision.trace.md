# Major 012 Watcher Session And Operator Interaction Repair — Anchor Reconciliation

Anchor accepts Loom's 0.1.4 host-only repair as the current technically qualified basis for another bounded Sigma dogfood. Major 012 remains open and no publication is authorized.

## Decision

- State: accepted-for-human-dogfood
- Subject: Tiinex/vscode 0.1.4 watcher-session and Operator-interaction repair
- Decision: accept the returned 0.1.4 candidate for human actual-path observation. Automatic discovery is session-scoped from extension watcher start forward, historical carriers remain manual-only, and the packaged Operator sidebar interaction wiring is repaired without moving Tiinex semantics into the VS Code adapter.
- Operative Effect: Sigma may install and naturally use the exact 0.1.4 VSIX. Anchor will reconcile the observed behavior before any Major 012 closure or publication disposition.

## Basis

- The Loom return carrier qualifies Business, Docs, Site, and vscode and reaches grounded-to-act under explicit Anchor holder binding with no blockers.
- Loom reports the carried 0.1.3 baseline at 27/27 bridge cases and repaired 0.1.4 at 28/28 with focused regressions for session-boundary watcher behavior and generated Operator client-script parse/binding.
- Full VS Code validation passed locally, including TypeScript/build/test/VSIX qualification.
- The returned candidate is `dist/tiinex-vscode-0.1.4.vsix`, 5,664,933 bytes, SHA-256 `91586e48248481b1313dd91ae9e750291548d5ade213e3b331dbdd7063e3661d`; Anchor independently verified that exact size and digest from the qualified carried vscode Workspace.
- Automatic startup backlog scanning is removed. Auto discovery now records a watcher-session start time and accepts only supported Handoff Package observations at or after that boundary; older carriers remain reachable only through explicit manual selection.
- The frozen Operator panel was traced to invalid generated inline JavaScript before listener registration. The client script is now generated through a parse-tested helper with escaped newlines, hardened inline JSON, and preserved nonce CSP.
- No Site shared semantic/core source change was required; this tranche remains a host lifecycle/presentation repair.

## Human Dogfood Boundary

- Sigma should use the extension naturally rather than reproduce Loom's automated qualification.
- Highest-signal checks are whether old Downloads carriers stay silent after startup, one newly arriving supported carrier produces the expected native prompt/state, and all visible Operator controls are actually interactive in the packaged VSIX.
- Existing diagnostics/Quick Fix, authoring, package-builder, multi-root, and landing surfaces remain in ordinary usability scope; this tranche primarily repairs the watcher session boundary and dead panel interaction.
- No commit, push, publication, formal test matrix, or manually manufactured return Handoff is required from Sigma merely to satisfy this dogfood gate.
