# Major 012 Supersession / Recovery Boundary — Anchor Decision

## Decision

- State: superseded-by-continuation-major-not-functionally-closed
- Subject: Major 012 — VS Code Human Operator Bridge
- Decision: stop extending Major 012 in the current Anchor conversation and continue the unfinished trust/operator work as Major 013 under a new cold-started Anchor. This is a continuity/operational major bump caused by conversation hard-limit pressure and accumulated orchestration latency, not a claim that Major 012 achieved its Done Criteria.
- Source Boundary: the exact durable full-source recovery base is the qualified 0.1.5 Anchor-to-Sigma carrier. Several later Anchor implementation attempts were verified transiently in subsequent runtimes but were not carried into a surviving full-source package before resets; those bytes must be replayed/reimplemented and requalified rather than called recovered source.

## Basis

- The recovered carrier SHA-256 is `f6a5068450d3a302295598cca54e794cdd79ce3b007d2674de009124e695ab40` and its Business, Docs, Site and vscode Workspace bindings independently qualify clean through the carrier context audit.
- The carried vscode source is the 0.1.5 dogfood baseline. The separately re-uploaded `tiinex-vscode-0.1.5(1).vsix` is byte-identical to that carried 0.1.5 VSIX (`d95c8a7d3dcb989511e362a2d4c5c62b5937c54c8f36ec3cf003016a4f4abdec`) and therefore contributes no newer recoverable implementation state.
- Sigma's 0.1.5 dogfood exposed a systemic trust/UX gap rather than one isolated bug: permalink Quick Fix failure, unclear/poorly anchored diagnostics, Handoff authoring/package failures, missing Role/Party endpoints, inability to use active Parent reliably, incomplete multi-root Workspace inventory, and insufficient confidence to exercise destructive landing/discovery.
- Subsequent direct Anchor work established a clear intended direction: Docs-first validation trust, shared Site core as semantic/mechanical source of truth, thin VS Code presentation/host integration, scoped/active-lineage validation, staged-only pre-commit validation, and one multi-root operator-context projection. Those later source bytes are not carried here and remain replay work.
- Measured local validation/test runtime in prior iterations was generally seconds/tens of seconds while conversational turns repeatedly approached ~25–30 minutes and one external fetch/tool path effectively stalled for hours. The next Anchor should optimize for fewer orchestration roundtrips and frequent durable checkpoints, not broaden audits by default.

## Supersession Boundary

- Major 012 is not declared durably complete, accepted, landed, or released.
- Major 013 inherits the unresolved Major 012 product objective and all still-applicable authority/safety boundaries, but treats the recovered 0.1.5 source as the last exact durable implementation base.
- Any implementation detail remembered from later transient Anchor sessions is a replay specification only until reimplemented and proven in the carried source lineage.
- No VSIX binary is committed or treated as canonical source. The outgoing recovery carrier intentionally omits the carried 0.1.5 VSIX build artifact; the new Anchor must build the next candidate from source.
- Playthings remains a separate branch/parallel track and a legitimate host/adversarial test setup. This decision does not merge/sync Playthings into Refactor.
- Loom remains optional. The new Anchor may reintroduce Loom only when a bounded specialist handoff is likely to reduce time-to-qualified-value.

## Next Major

- Open Major 013 — Validation Trust + Thin VS Code Operator Consolidation.
- First priority: replay the lost trust-spine changes into shared Site Tooling with permanent tests and frequent checkpoints.
- Second priority: consume those shared projections from `Tiinex/vscode` without duplicating semantic logic or a second independently evolving core.
- Sigma is invited to dogfood only after the internal Docs/ordinary-trace/multi-root/staged/package/build gates are green and the new VSIX is built from the carried source.
