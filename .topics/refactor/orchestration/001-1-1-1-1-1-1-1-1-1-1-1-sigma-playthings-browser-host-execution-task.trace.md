# Sigma Playthings Browser Host Execution — Site Major 005

## Objective

Execute the qualified Site Major 005 local-source browser harness on Sigma's dependency-capable Windows host using the exact carried Tiinex source set, and return one machine-readable result that either proves a genuine real-browser PASS or identifies the smallest exact remaining host blocker.

## Done Criteria

- Use only the exact carried Site, Core, App and Verse Playthings source included in this Handoff package.
- Do not publish, commit or push any `@tiinex/*` package merely to make the test run.
- Run the Site-owned local-source harness exactly once from the prepared local checkouts after applying the carried source.
- Public npm access may be used only for the exact declared third-party dependencies in Site's lockfile.
- Use Sigma's already installed Chrome/Chromium executable explicitly when the harness cannot resolve one automatically.
- Return the resulting `result.json` or the exact structured failure stage/output to Anchor without manually repairing source during the test.
- If `status: passed` and `realBrowser: true`, preserve the browser result as technical evidence only; this does not yet equal Playthings human acceptance.

## Dependencies

- Exact carried Site, Core, App and Verse Playthings source from the current full Handoff package.
- Node/npm satisfying the carried package engine constraints.
- Normal public npm access or cache for exact declared third-party dependencies only.
- An installed compatible Chrome/Chromium executable when automatic resolution is unavailable.

## Scope

Human-host execution of an already qualified test harness only. No product changes, no source debugging, no package publication, no ad-hoc symlinks, no first-party dependency substitution, and no acceptance decision beyond reporting the observed result.

## Why This Exists

The Site Major 005 implementation removed the first-party publication ambiguity and proved exact local packing. The role host could not reach public npm, so the final real-browser gate must run on a normal dependency-capable host. This task turns that environment gap into one bounded Sigma execution step rather than loose manual troubleshooting.
