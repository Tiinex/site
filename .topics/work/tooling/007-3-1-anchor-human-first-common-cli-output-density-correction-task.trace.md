# Human-First Common CLI — Output Density Correction

## Objective

Reproduce and minimally correct the remaining human-first CLI ergonomics defect exposed by Sigma's fresh acceptance observation: the one public common path is semantically qualified and no-glue, but its default output is still receipt-scale and machine-first enough to impose avoidable human/LLM reading and token cost.

## Scope

- Shared portable Site Tooling only.
- Default rendering/progressive-disclosure behavior for the existing common path, beginning with `orient`, `ground`, and `ground --continue` and extending to `author`/`handoff` only where the same default-output defect is reproduced.
- Existing commands and one-surface human/LLM semantics must remain shared.
- Add permanent regression coverage only for stable invariants introduced by the correction; keep the existing Foundation spine coherent.

## Required Investigation

Use the returned fresh-acceptance carrier as a control and follow explicit RCA discipline:

`observed output-cost symptom → reproducible command/output measurement → owning rendering/composition layer → root cause → minimum correction → regression → fresh acceptance candidate`

Do not assume the fix is merely deleting JSON fields. Determine which default projection is needed for the immediate user decision and which evidence can move behind deliberate detail discovery without weakening correctness.

## Acceptance Invariants

- One public CLI surface remains the same for humans and LLMs; do not create an LLM-only façade or separate semantic implementation path.
- `orient` default output should expose only the bounded route/workspace orientation needed to continue, plus exact next action; deep package/endpoint/closure receipts remain deliberately discoverable.
- `ground` default output must preserve the decision-critical contract: readiness state, recipient role/authority boundary needed to act, current Task/frontier identity, Required Context closure, continuity/root/blocker state, and exact next action. It must not require receipt-scale projection when the route is clean.
- `ground --continue` should report the materialization result and bounded current work needed to proceed without repeating a full grounding receipt by default.
- When blocked/degraded, the compact default must remain fail-visible and include the exact actionable finding/recovery step; compression must never create false green.
- Full qualified receipts remain available through an explicit detail/diagnostic path on the same CLI surface.
- Common-path defaults must remain deterministic and suitable for both humans and LLMs; no hidden host memory or connected-provider behavior may be required.
- Preserve carrier-major `006` grounding/recovery invariants, canonical artifact/package semantics, and the successful author/handoff no-glue path.

## Measurement Baseline

Anchor replay on the exact accepted return carrier measured:

- `orient-handoff-package`: 15,183 raw output bytes / 331 lines.
- `ground`: 19,826 raw output bytes / 384 lines.
- `ground --continue`: 78,991 raw output bytes / 408 lines.

Treat these as reproducible raw-output baselines, not token counts. Record before/after output volume for the corrected default commands and verify that deliberately requested full/detail receipts still preserve the qualified evidence.
