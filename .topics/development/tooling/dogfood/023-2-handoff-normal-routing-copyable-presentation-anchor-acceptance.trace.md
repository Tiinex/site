# Tooling 023 Anchor acceptance

## Decision

- State: accepted-bounded
- Subject: normal Handoff one-primary-plus-copyable-routing presentation contract
- Decision: accept Tooling 023's portable implementation. Normal Handoff output now carries one sole primary package choice, exact package-derived `normalInlineRouting.content`, explicit copyable-surface and host-capability presentation metadata, and an explicit normal-emission boundary excluding internal `humanOutput` JSON, helper artifacts, semantic work-summary prose, manually reconstructed routing, duplicate normal file choices, and fallback sidecars unless the user explicitly asks for explanation or review evidence.
- Trust Level: portable presentation/projection mechanics accepted / wrapper remains non-authoritative / prior Loom host rendering not independently reconstructed from package bytes / no Role qualification claim

## Basis

- Independent replay passes `humanOutputCopyablePresentation.test.mjs`, `humanOutputNormalEmission.test.mjs`, `carrierProjection.test.mjs`, the full `portable.test.mjs` aggregate, and Handoff manufacture scale over 1,286 workspace carriers / 1,306 package files.
- Direct `project-handoff-carrier-output` replay against the returned `tiinex-site-016-loom-to-anchor.handoff-package.zip` is `ready` and reproduces the exact route bytes while exposing `copyableSurfaceRequired: true`, `exactContentRequired: true`, `fencedCodeBlockWhenSupported: required`, wrapper authority `none`, and the expected normal-emission exclusions.
- Source review confirms `humanOutputPresentation.js` keeps host presentation separate from routing content; `carrierProjection.js`, manufacture summaries, CLI help, and bootstrap all consume the same host-capability rule without embedding Markdown fences or other UI syntax in `normalInlineRouting.content`.
- `npm run validate` still stops at the supplied-baseline v119 source-size guard for only `src/tooling/portable/engine.facade.js` and `src/tooling/portable/operation.catalog.js`; the Tooling 023 modified carrier projection remains below the guard and the complete portable aggregate passes independently.

## Consequences

- Tooling 023 is closed at the bounded portable mechanics layer.
- The human-visible cold-start gate remains separate: package bytes cannot reconstruct whether the prior Loom response was visibly rendered as a fenced/copyable block in the chat UI. Q or another fresh observer may qualify that actual host behavior from the visible response; this acceptance does not infer it from routing bytes alone.
- Fenced Markdown remains a host wrapper, not canonical Handoff semantics. Equivalent copyable surfaces remain valid on hosts without fenced blocks.
- This decision does not change Tooling 021/022, publication authority, lineage mutation authority, or Loom Role qualification.

## Review Conditions

Reopen Tooling 023 mechanics if a ready selected-route manufacture or read-only package projection can alter routing bytes, expose more than one normal package choice, make the fallback sidecar normal, omit the presentation boundary, or allow host wrappers to become package/canonical authority. Reopen actual-host qualification separately if a fresh Role still emits normal Handoff routing as non-copyable prose or surrounds the fast path with unrequested semantic summary output.
