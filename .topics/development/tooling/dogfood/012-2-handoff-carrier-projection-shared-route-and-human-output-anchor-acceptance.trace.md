# Tooling 012 Anchor acceptance

## Decision

- State: accepted
- Subject: shared Handoff carrier route projection, one-primary human output, deterministic carrier naming, and per-route recipient grounding qualification
- Decision: accept Tooling 012 at the bounded portable Tooling architecture/source boundary. One immutable Handoff carrier may expose multiple independently qualified routes over common carried bytes; shared mode requires explicit route selection; each advertised route must independently prove its own Required Context from exact carried workspace/material bytes before transport can be executable; Reference Context remains non-blocking; outer filename/dimension/transport text remain disposable human projections without semantic authority.
- Trust Level: bounded implementation acceptance / not canonical Handoff-schema acceptance / not Viewer product acceptance
- Does Not Mean: multi-workspace authoring is closed, a parseable cold-consumer entrypoint is implemented, filenames or dimensions create Parent semantics, package inclusion assigns work, every Reference Context item must be carried, or shared carriage implies shared acceptance.

## Consequences

- Tooling 012 is closed for deterministic human carrier projection, shared-route fan-out over one immutable package, one-primary normal transport output, optional regenerable transport-text fallback, explicit shared-route selection, collision-only transport suffixes, and route-local Required Context qualification.
- A shared carrier may reuse common workspace/material/bootstrap bytes across recipients without human prose overriding package route truth.
- Missing Required Context on any advertised shared route blocks shared human routing/transport executability until exact carried material qualifies that route; missing Reference Context alone does not.
- Tooling 011 remains the accepted single-route manufacturing/bootstrap fallback and was not redesigned by this leaf.
- Parseable cold-consumer package entrypoint and multi-workspace-aware projection remain separate follow-up work owned by the existing feedback artifact rather than retroactively folded into this acceptance.

## Review Conditions

Reopen Tooling 012 only for a reproducible contradiction in carrier projection qualification, deterministic naming/collision behavior, explicit shared-route selection, common-byte reuse, per-route Required Context closure, transport-text regeneration, package-control rehydration, or Tooling 011 compatibility. Route cold-consumer entrypoint, multi-workspace capability, or Viewer activation to their dedicated follow-up work.
