# Q PoC versus refactor product-feel feedback

## Observed Signal

- Q performed an unannounced actual-path comparison by loading and inspecting the same current Site source ZIP first in the retained PoC and then in the refactored Viewer, followed by broader navigation/interaction in both.
- In the PoC, workspace intake quickly forms one coherent working object with Feed/Tree, search, artifact cards, reader/lineage, obvious next actions, and strong spatial continuity. Opening an artifact feels like going deeper inside the same knowledge/work room rather than switching into a diagnostic surface.
- The PoC's multi-workspace/column experience makes separate material contexts visually simultaneous without collapsing their identities; this is a strong product expression of the Universe/Multiverse/Column Verse direction.
- The refactor already exposes materially stronger truth and authority boundaries: source-backed/display-hidden/lineage-usable distinctions, schema/fallback state, explicit GitHub read-only/source behavior, separation of saving source from loading material, no inferred GitHub provenance, qualified creation contracts, and separation between storage placement and Parent/Reference/source provenance.
- The refactor currently lets runtime/qualification accounting compete visually with the artifact and its likely next action. Product use therefore trends toward "inspect Tiinex correctly" more than "work in Tiinex naturally" in the demonstrated path.
- Lineage and Tree are functionally substantial in the refactor, but the PoC more strongly communicates following an artifact's story and arranging/navigating knowledge rooms rather than reviewing a correct resolution model.

## Source

- Source: Q actual-path host observation from an approximately 6.5 minute screen recording reviewed by Anchor at one frame per second without audio, plus Q's explicit statement that this was a small product-feel demonstration intended to improve Anchor grounding rather than a formal acceptance run.

## Interpretation

- The refactor is not a blank product reconstruction: significant semantic/runtime truth rigor already exists and must not be discarded merely to imitate old visuals.
- Retained PoC parity should recover observable product qualities on top of the qualified architecture: information prioritization, spatial continuity, interaction rhythm, obvious next action, artifact-first reading, and progressive disclosure of diagnostic/runtime detail.
- "PoC feel" is therefore legitimate product evidence rather than an instruction to copy old CSS or revive superseded implementation mechanisms.
- Q actual-path observation is especially valuable for tempo/instinct: where a human proceeds without deliberation versus where the interface makes the user inspect controls/state is evidence automated source tests cannot manufacture.

## Feedback Target

- Target: refactor parity planning and later Kodax Viewer integration/recovery tranches, especially Load -> Read -> Trace and multi-workspace/Verse product behavior.

## Feedback Received

- Anchor disposition: preserve this as product/host evidence and use it when shared capabilities are later presented in Viewer; do not prematurely pull Q into low-level mechanical QA that LLM/tooling pressure should catch first.

## Evidence Material

- Retained PoC product signals: coherent workspace object; Feed/Tree/card hierarchy; Reader/Lineage continuity; obvious action affordances; multi-column/multi-workspace spatiality.
- Current refactor product signals: strong source/provenance/schema/creation/lineage truth projection; diagnostic/runtime state often foregrounded; weaker current spatial/interaction feel relative to PoC.
- Existing macro exit authority remains [Macro Roadmap And Refactor Exit Recovery](001-2-1-macro-roadmap-refactor-exit-recovery-result.trace.md): retained PoC behavior must be requalified or explicitly superseded before refactor completion.

## Disposition

- State: accepted-product-evidence/open-parity
- Follow-Up: use this evidence to define coherent later Viewer recovery tranches after shared portable logic is stable enough to consume; Q should receive actual-path QA at meaningful product milestones rather than being the first-line detector for parser, package, schema-material, or cross-role regressions.
- Qualification Effect: strengthens confidence that remaining parity work is primarily qualification/integration/product-recovery pressure rather than a need to redesign Tiinex semantics from scratch; does not itself accept any current parity scenario.

## Limits

- This is not formal Q acceptance, not a complete retained-PoC parity audit, and not a timing benchmark.
- The recording does not establish that every PoC behavior should survive unchanged or that every refactor diagnostic should be hidden.
- Product feel must remain constrained by current semantic/source/authority truth; superseded PoC mechanics are not revived solely because they felt familiar.
