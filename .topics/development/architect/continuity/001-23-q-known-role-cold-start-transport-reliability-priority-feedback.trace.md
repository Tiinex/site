# Q known Role cold-start transport reliability priority feedback

## Feedback Target

- Target: known Role cold-start qualification, Role-to-human-to-Role Handoff completion, Tooling-owned human transport projection, and current foundation trust closure.
- Not Target: canonical Role/Handoff semantics, Viewer product parity, Process schema content, Source semantics, or whether internal result/receipt artifacts may exist inside a package/workspace.

## Feedback Received

- Q will not count a same-session correction as proof that a Role follows the Handoff return routine reliably. A fresh Role conversation in a new ChatGPT project is required before Q considers that Role's current cold-start behavior qualified.
- The latest fresh Loom run independently recovered Tooling 015-017 scope and Role boundaries, completed the bounded implementation, and manufactured a qualified return package, but its first human-visible return exposed multiple internal result artifacts and omitted the established copyable routing block.
- After explicit correction, Loom first produced an improvised summary transport block instead of Tooling's established human-output projection. After a second explicit correction instructing it to use Tooling's qualified human output, the same session returned one primary Handoff ZIP plus the established copyable routing block.
- Q treats these final-meter transport failures as foundation friction and trust blockers even when implementation/regression behavior underneath is correct. Requiring Q to choose files, infer the controlling route, or teach a Role the return format makes the workflow operationally unreliable.
- Q therefore prioritizes known Role cold-start trust closure now: Anchor, Axiom, Loom and Kodax should each be exercised from a fresh project/conversation using package-local grounding and minimal host routing, and should complete return transport without coaching.
- Tooling should own the transport projection. A Role may perform semantic/technical work and invoke manufacture/projection, but should not invent a replacement transport summary, expose helper artifacts as human choices, or reinterpret the route in prose when qualified package-derived output already exists.

## Source

- Q actual-path observation and screenshots from the fresh Loom Tooling 015-017 run and its two same-session human-output corrections.
- Existing accepted host transport feedback and Handoff human-output correction artifacts carried in the current Site workspace.

## Disposition

- State: accepted-for-current-dogfood-priority
- Follow-Up: before declaring the known Role foundation trusted, run fresh-project cold-start qualification against the current Tooling/Handoff generation for Anchor, Axiom, Loom and Kodax. Treat coached same-session correction as diagnostic evidence only, not qualification.
- Transport Gate: a qualifying Role return exposes exactly one primary recipient-relative Handoff package and the Tooling-derived fenced/copyable minimal routing block, with no internal artifacts requiring Q selection and no Role-authored substitute transport representation.
- Priority Effect: defer nonessential feature expansion when it competes with closing the cold-start/return path for known Roles. Existing bounded semantic work may remain preserved, but foundation trust is not declared until the actual-path routine is boring and repeatable.

## Limits

- One fresh-project success is qualification evidence, not a universal proof that every host/model version will behave identically forever; later contradictory actual-path evidence reopens the relevant gate.
- This feedback does not make current Role identity materialization complete, does not decide Role artifact canonical home, and does not authorize rewriting historical Architect/Schemer/Tooling/Dev artifacts.
- The human-output rule does not forbid internal package controls, receipts, result traces or validation artifacts. It forbids making Q select or semantically interpret them for normal transport.
- A package-local Pointer entrypoint and `START.md` may coexist while their migration contract remains under Tooling/Anchor acceptance; neither permits a Role to improvise a human route that disagrees with qualified package truth.
