# Playthings Generative Visual Source Production

## Current Read

Generative image production is used to create bounded visual source, not runtime precision. Motion, identity, layout, object/style variance, or other concerns may be supplied as separate visual authorities. The strongest demonstrated path for locomotion used an externally authored eight-frame walk-cycle authority plus a separate Plaything identity authority; equivalent input material produced useful results both in an isolated generation context and in the working conversation.

## Production Turn

1. **Bound the source task.** Define what visual family is being produced and which properties are semantic/visual acceptance targets. Do not require the generator to invent motion mechanics when a suitable reusable motion authority exists.
2. **Compose authority inputs.** Prefer a small ordered authority set where each image has one legible job: motion/pose, identity, structural layout, object/place variance, etc. Accepted seed sheets may themselves become future structural authorities.
3. **Emit bounded user input.** The originating/reviewing role may package the exact attachments, order, roles, and human-visible instruction for a Pilot-mediated external execution. User text should express intent/semantic constraints while images carry spatial or motion structure when possible.
4. **Pilot execution.** Pilot guides the human through the external model/tool boundary, preserves actual inputs/result, reports host/provider anomalies, and returns immediately without visual acceptance.
5. **Technical post-check.** Verify exact source bytes, dimensions/grid, alpha, occupancy/spill, and deterministic split. For motion, create a stabilized transparent review without changing pose content.
6. **Deterministic normalization/surgery.** Whole-frame alpha-aware movement, shared scaling, centering, baseline alignment, safe margins, reorder/drop/copy/replace/duration variants are allowed when recorded. These operations do not authorize generative repainting and never overwrite the exact generated source.
7. **Human/owner review.** Ordered contact/source sheet is primary semantic evidence for frame content; lossless animated WebP is the preferred transparent motion preview. Review identity/style, motion semantics, loop continuity, spacing, and the property the source task actually targets.
8. **Disposition and promotion.** Reject/retry, preserve as process evidence, or accept. Accepted stable visual assets are promoted outside .topics into 'reference/playthings/...' or another natural domain location with lineage stem/hash linkage. Transient attempts remain lineage-local/package evidence until safe reduction.

## Technical And Motion Gates

Technical/spatial gates include correct count/grid, one intended subject per slot, alpha integrity when requested, isolation/safe margins, consistent usable scale, and deterministic extraction/normalization success. Motion-semantic gates include readable progression, support/swing separation, weight transfer, rise/fall where appropriate, natural opposing arm swing, no accidental near-duplicate hold at adjacent/wrap boundaries, and a continuous stabilized preview. Passing technical gates does not imply passing motion/visual gates.

## File And Lineage Convention

Files created by an active execution/review moment share its lineage dimension and directory where practical. For example, an Evidence named '003-3-1-2-...evidence.trace.md' may be accompanied by '003-3-1-2-generated-01.png'. Review derivatives from a later accepting moment may use '003-3-1-4-review-01.webp'. Native image/JSON/Markdown extensions remain native; only semantic Tiinex artifacts use '.trace.md'.

Once stable, the selected asset moves out of .topics while retaining lineage in its filename/path and immutable links/hashes from the Evidence. Rejected attempts are not promoted merely to keep them around. This lets current source retain decision/history semantics while production-ready assets live in their domain surface.

## Review Formats

- Canonical/generated still source: PNG; preserve exact returned bytes before transforms.
- Transparent human motion preview: lossless animated WebP.
- APNG may be used for compatibility/technical checks.
- GIF is not alpha-authoritative.

## Reuse Direction

After one member of a sheet family is accepted, prefer reuse: accepted sheet as structure/motion authority plus a separate variance/identity/object reference. This reduces the amount of layout, timing, and motion mechanics the generator must rediscover. Do not assume reuse is universal; record the authority set and review each family.

## Interpretation Limits

- Does Not Mean: image-generation model output is runtime-ready by default; every visual family needs 8x8 sheets; all providers interpret multiple references identically; or Pilot owns source acceptance.
- Must Not Be Used To Claim: exact provider-internal prompt equivalence, schema truth encoded in pixels, or permission to keep every transient generation permanently in stable reference storage.
