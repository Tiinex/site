# UX Ergonomics

Tiinex UI should not create clarity by over-explaining every control. It should make repeated work fast through form, position, color, rhythm, affordance, and consistent behavior.

## Rule

Use text for names, labels, status, risk, and explicit boundary disclosure. Put longer explanations in help, tooltips, details, docs, or handover material instead of the primary workspace.

## Applied Shape

- Workspace frame first.
- Verse content owns most of the visual area.
- Source truth remains visible as compact chips.
- Diagnostics and schema grounding are secondary.
- Actions stay close to the artifact.
- Mobile should show value first and controls second.

## Not A Dumbed-Down UI

The user is allowed to learn a coherent system. Tiinex should make the system visible and consistent rather than hiding power behind prose.
