# Interaction Spine

The interaction spine is the compact action rhythm for the Tiinex workspace.

It exists because v89 exposed useful capabilities but did not make the primary workflow obvious. The fix is not more prose. The fix is clearer placement, grouping, state, and affordance.

## Human-First Rule

A reader should be able to see the next likely action from shape and position before reading a paragraph.

## Spine Steps

- Load
- Read
- Trace
- Audit
- Act

## Boundaries

- The spine may switch arrangement or reader disclosure.
- The spine must not change source truth.
- Audit remains explicit and user-invoked.
- Scaffolded actions must look scaffolded or unavailable.
- Future create/share/source actions must keep draft/source boundaries visible.

## Legacy Lesson

The legacy app worked well because action clusters lived near the artifact and the mode row gave fast transitions between Discovery, Tree, and Lineage. v90 preserves that lesson without importing `.old` runtime code.
